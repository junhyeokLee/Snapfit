# 결제 복구·안내 수정 계획

**Goal:** 승인된 결제 검토 1~4번을 모두 수정한다.
**Spec:** docs/verification/payment-audit-2026-11-16/결제_검토결과.md (사용자 전체 실행 승인).
**Architecture:** 기존 Flutter/Riverpod 결제 서비스·저장소를 유지하고 실패와 미확정 상태를 구분한다. 실제 결제 금액·보상·서버 권한 정책은 변경하지 않는다.

## 제약
- 기존 dirty 작업 보존. 커밋·초기화·앱 전체 빌드·배포·운영 주문/금융 조회 없음.
- 무거운 컴파일·테스트·렌더는 한 번에 한 프로세스.

## 작업
- [x] 인쇄: 실제 서비스가 이미 서버 검증한 영수증을 재사용. 주입 callback의 서버 재검증·소유자/금액 검사는 유지. 두 번째 조회 실패로 신규 결제가 열리는 회귀 사례를 안전 기대값으로 추가.
- [x] 포인트: 승인/SDK 응답 timeout은 확인 지연으로 유지. 미확정 구매 marker를 기존 영수증과 별도 보존하고 동일 계정 복구 전 새 구매를 막는다. 빈 복원 결과로 취소를 추정하지 않는다. 늦은 성공/취소/계정 전환·재시작·저장 실패 테스트.
- [x] 상품: 상품 목록 재조회 실패 시 캐시 표시와 구매 가능 여부를 구분. UI와 서비스의 중복 진입 가드를 함께 검증.
- [x] UI: 확인 지연 안내·원래 결제 상태 복구 행동·캐시 목록 재조회 행동을 표시. 결제 준비 상태와 버튼의 문구를 일치시킨다.
- [x] 동의: 남은 필수 확인 개수와 다음 미확인 항목으로 이동. 선택을 자동 체크하지 않는다. 네이티브 lazy 목록·웹공통행동·큰글씨 확인.
- [x] 관련 테스트 직렬 실행·정적 분석·새 화면 캡처·독립 리뷰. 실결제 검증의 한계를 정확하게 기록.

## 완료 근거
관련154개 테스트·별도5개 캡처 사례 통과, Dart10파일 분석 문제0. 독립 리뷰 수정 반영. 미식별 스토어 응답의 보수적 차단/고객센터 경로 및 실기기 미검증 범위를 적용 보고서에 기록했다.
