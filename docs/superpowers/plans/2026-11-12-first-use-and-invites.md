# 첫 사용 안내와 다음 초대 개선

**목표:** 월간 기록을 가리지 않는 짧은 첫 안내와 같은 권한으로 다음 사람을 초대하는 명시적 행동을 제공한다.
**근거/승인:** `docs/verification/next-ux-audit-2026-11-12/README.md`의 개선 2건을 사용자가 승인했다. 요청한 용량 정리를 먼저 완료했다.
**구조:** 기존 FirstVisit Riverpod 상태·콜백·권한/계정 격리와 초대 발급 메서드를 재사용한다. 새로운 저장소나 의존성은 추가하지 않는다.

## 제약

- 오늘 기록을 먼저 안내하고 `앨범 바로 만들기`를 보조 선택으로 유지한다.
- 팝업으로 달력과 진행률을 덮지 않는다. 큰 앨범·작은 선택 목록·달력 크기·1,000P/당일 사진 정책을 바꾸지 않는다.
- 유효 journal일 때만 첫 안내를 소비한다. 숨은 탭, 계정/route 전환, 재요청과 닫기, 건너뛰기 이력을 보존한다.
- 초대는 현재 선택한 역할로 새 링크를 만들고 준비 중 복사·공유·중복 발급을 차단한다. 기존 복사/공유의 링크 재사용과 오류 재시도는 유지한다.
- 서버 작업·메시지 전송·앱 전체 빌드·상시 서버·Git 변경 없이 검증한다. 무거운 실행은 루트 한 프로세스만 수행한다.

- [x] 재생성 가능한 임시 커널 37개와 추적되지 않는 build/컴파일 캐시를 정리한다. 원본·작업 코드·기존 웹 자산 이력·최종 결과물을 보존하고 native 검증 메타데이터를 분리한다.
- [x] 첫 안내/소개/새 초대 동작의 실패 테스트를 실행한다.
- [x] 월간 기록 내부에 인라인 안내를 배치한다. `오늘 기록하기`/`앨범 바로 만들기` 콜백과 한 번만/수동 다시 보기/유효 상태 조건을 검증한다.
- [x] 소개 2장에서 매일 기록과 즉시 앨범 제작 두 출발점을 설명한다. 아트워크는 유지한다.
