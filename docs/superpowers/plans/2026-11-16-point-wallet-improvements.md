# 포인트 1~5 개선 구현

사용자는 포인트 검토 결과에서 먼저 권장한 1~5번의 적용을 승인했다. 알림·고객센터 답변·초대·웹 AI 신규 개편은 이번 범위에 포함하지 않는다.

기존 SnapFit 청록색·번들 글꼴·공통 폼 토큰을 재사용한다. 충전 전에는 상품/필요P/부족분과 예상 잔액을, 충전 후에는 검증된 완료 결과와 원래 작업 복귀를 우선 표시한다.

1. 표시 전용 PointTopUpContext(ownerId,productKey,title,requiredPoints)를 전달하고 현재 계정에서만 표시한다. 돌아온 상품의 가격·잔액·소유권은 계속 서버에서 다시 확인하며 자동 구매하지 않는다.
2. 서버 검증·스토어 완료·복구 상태 정리가 성공한 경우에만 typed completion을 제공한다. 현재 계정으로 제한하고 alreadyGranted는 추가 지급으로 표시하지 않는다. 기존 금액·동의·영수증·불확실 결제 가드는 유지한다.
3. 잔액 카드는 음수를 정산 상태로 명확히 표시하고 숫자/단위를 분리하지 않는다. 선택 상품과 확인된 잔액이 있을 때 정수로 예상 잔액을 계산한다. 조회 중/실패를 0으로 바꾸지 않는다.
4. 정상 충전·원장에도 기존 이용/환불 정책과 고객센터로 연결한다. 정책이나 환불 상태/금액은 새로 추정하지 않는다.
5. 가격 변경 시 새 가격 확인 Action을 제공하고 기존 gate Future를 유지한 채 같은 상품을 다시 조회한다. 새 가격에 대한 별도 사용자 확정을 유지한다.

검증: 기존 public API로 UI·가격변경 RED 확인 → 범위별 구현 → 서비스/구매/계정/복구/원장/반응형 회귀와 새 캡처 → 독립 리뷰. 모든 무거운 프로세스는 하나씩 실행한다. 실결제·운영 DB·앱 전체 빌드·배포는 하지 않는다.

진행: 1~5번 구현·RED/GREEN 검증·독립 리뷰 완료. 관련 테스트 129건과 화면 재현 11건 통과, 새 PNG 17장 확인. 정적 분석 문제와 테스트용 커널 컴파일 오류 0건. 가로·큰 글씨 완료 화면은 본문 공간을 확보하도록 추가 수정했고 관련 회귀도 통과했다. 결과는 `docs/verification/point-wallet-improvements-2026-11-16/적용_결과.md`에 보관했다. 실결제·운영 DB·앱 전체 빌드·배포는 실행하지 않았다.
