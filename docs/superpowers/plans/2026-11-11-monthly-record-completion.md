# Monthly Record Completion Implementation Plan

**Goal:** 승인된 월간 기록 홈을 다듬고 한국 시간 당일 사진 기록만 인정해 한 달 전체 날짜 완주 시 1,000P를 월 1회 지급한다.

**Architecture:** 기존 Flutter/Riverpod 기록·선택 앨범 흐름을 유지한다. Supabase의 기록 저장과 월간 상태 응답에 서버 기준 날짜 검증과 원자적·멱등 보상을 연결한다. 기존 출석 보상과 지갑·원장은 보존한다.

**Spec:** 이 대화에서 선택한 두 번째 홈 시안과 2026-11-11 사용자 수정사항. 사진은 비율을 보존하고 홈의 대각선 화살표를 제거한다. 월간 기록이 앨범으로 이어짐을 안내하고 선택한 큰 앨범 아래 작은 썸네일 선택을 유지한다.

## Global Constraints

- 기준 날짜는 서버 Asia/Seoul, 보상은 1,000P, 사용자·달마다 1회. 월별 실제 일수와 윤년을 적용한다.
- 지난 날짜의 새 기록·사진 추가/교체·날짜 이동은 차단한다. 기존 기록 조회·앨범 사용·삭제는 보존한다. 기존 글 수정은 사진을 바꾸지 않는 범위에서 유지한다.
- 기록당 최소 사진 1장. 같은 날 여러 기록은 달성 일수 1일로 센다. 실제 당일 저장된 유효한 사진 기록만 보상에 인정한다.
- 이전에 소급 입력한 기록을 당일 인증으로 간주하지 않는다. 이미 저장된 동일 요청의 자정 이후 재시도는 성공 결과를 복원한다.
- 기존 작업 파일 986개가 수정돼 있어 현재 내용 위에 최소 변경을 적용하고 /tmp/snapfit-monthly-completion-before 기준과 비교한다. git 체크아웃·리셋·커밋은 하지 않는다.
- 앱 전체 빌드·상시 서버는 실행하지 않는다. 무거운 검증은 한 번에 1프로세스, Flutter 테스트 동시성 1.

## Review Focus

- 자정 직전 업로드·자정 이후 저장/재시도, 기기 시간·날짜 조작.
- 동시 저장·중복 재시도·이중 포인트 지급·다른 계정 데이터 접근.
- 2월·윤년·월말·월경계와 과거 기록/삭제.
- 날짜 선택·초안 복구·기존 기록 편집의 클라이언트/서버 일치.
- 세로/가로 사진·앨범 비율, 큰 글자·좁은 화면·선택 앨범 상태 보존.

## Tasks

- [x] Server: 기존 저장/지갑/원장 패턴에 날짜 제한·월간 보상·상태를 추가. 실제 PostgreSQL 호환 테스트로 날짜·월말·멱등성·권한 검증.
- [x] Client: 월간 보상 모델과 상태 응답을 추가하고 지난 날짜 사진 입력을 잠금. 자정/초안/오류 안내와 기존 포인트 적립 내역 표시를 연결.
- [x] Home: 선택 시안의 월간 기록·보상·앨범 연결 안내를 적용. 사진/앨범 비율 보존, 대각선 아이콘 제거, 큰 선택 앨범+썸네일 유지.
- [x] Integration: SQL 실행 검사·Dart 정적 분석·코드리뷰 완료. 서버 운영 적용 후 상태/권한 확인. 아래 미검증 범위는 별도로 유지한다.
- [ ] Widget runtime / visual QA: Flutter 테스트가 컴파일 단계에서 4분 30초 이상 진행되지 않아 중단. 테스트 본문 실행과 실기기 시각 검증은 미완료. 앱 전체 빌드·배포는 수행하지 않았다.

- 서버 22개 실행 검사(월간 9개·출석 13개) 통과. 단일 연결 PGlite 검사이며 다중 세션 부하 검사는 아니다.
- 코드리뷰에서 찾은 자정 후 기존/재시작 저장 재시도와 미래 기기 시계 문제를 수정하고 재검토 완료. 저장 요청 지문을 초안에 보존하며 서버의 현재 월 조회는 p_month:null을 사용한다.
