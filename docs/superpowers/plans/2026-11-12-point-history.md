# 포인트 이용내역 개선 계획

**목표:** 과거 포인트 내역을 정확하게 필터링하고 이어서 조회한다.
**구조:** 기존 BillingRepository의 요약 계약을 유지하고 상세 페이지 API와 필터별 Riverpod 상태를 추가한다. 기존 화면을 이용하며 새로운 화면·의존성·DB 스키마를 만들지 않는다.
**설계:** [포인트 전체 이용내역과 필터](../specs/2026-11-12-point-history-design.md)

## 작업

- [x] 현재 실제 provider/repository를 통과하는 최신 5건/6번째 차감 상태를 네이티브 캡처하고 실패 회귀를 확인한다.
- [x] `billing_repository.dart`: 필터·커서·페이지 DTO와 전용 조회를 추가한다. 본인 조건, 생성 시각+ID 순서, 서버 필터, 경계 검증을 테스트한다.
- [x] `billing_provider.dart`: 필터별 상세 상태, 더보기·새로고침·오류 복구·중복 차단·owner/generation 검사를 구현한다.
- [x] `billing_management_screen.dart`: 모바일/웹 로컬 5건 필터를 상세 상태로 교체하고 더보기·후속 오류·끝 상태를 보여 준다. 요약/충전/AI 복귀는 유지한다.
- [x] 기존 포인트 변동의 무효화 지점에 상세 provider 무효화도 연결한다. 해당 테스트 fixture를 신규 상세 계약에 맞춘다.
- [x] 관련 테스트·분석·전후 화면·독립 검토를 완료하고 임시 컴파일 파일을 정리한다.

## 검토 초점

기존 최근 5건 호환, 전체의 0P 기록·적립/차감 부호, 같은 시각 페이지 경계, 조회 중 새 거래 삽입, 후속 오류 후 원래 커서로 재시도, pending 중 새로고침과 계정 전환, 더보기 후 스크롤 위치, 충전 중 상태와 이전 AI 화면 복귀.

완료 근거: [전후 화면·검증](../../verification/points-history-2026-11-12/README.md). 기능 85건, 분석 18파일 이상 없음, 독립 검토 완료.
