# 기록에서 월간 앨범으로 이어지는 흐름

사용자의 전체 UX 개선 지속 요청에 따라 현재 화면에서 확인한 두 마찰을 고친다.

- 사진 36장·320×568 재현에서 만들기까지 3,972px(본문 약 7.82화면)을 내려가야 한다. 선택 수와 기존 만들기/추가/이어서 편집 행동을 하단 실행 영역으로 옮긴다. 큰 미리보기·사진 선택·표지 선택·최대 9장 제한은 유지한다.
- 홈의 직접 작성은 저장한 기록만 넘기므로 월 전체 상태를 알 수 없다. `hasCompleteJournal`을 명시하고 이 경로만 false로 전달한다. 저장 즉시 해당 사진의 저장 사실을 안내하며 전체 기록 조회를 추가하지 않는다. 서버 날짜 확인은 유지한다.

## 선택한 구현

버튼을 목록 위에 복제하는 방법은 스크롤 중 다시 사라지고 중복 동작을 만든다. 별도 사진 선택 단계를 만드는 방법은 제작 흐름을 늘린다. 기존 화면의 실행 영역만 하단에 두는 방법을 택한다. 색·글꼴·사진 크기와 실제 제작 함수는 재사용한다.

월 요약을 얻기 위해 저장 후 재조회하는 방법은 저장 완료 안내를 늦추고 실패 경로를 늘린다. 직접 진입과 전체 월 데이터를 받지 못한 임시 기록 복구에서는 확인된 저장 사실만 표현하고, 전체 월 데이터가 있는 기존 진입은 첫 장·누적 안내를 유지한다.

## 제약과 확인

하단에는 선택 수와 나만 보기 상태를 보여 주고, 오류·저장 완료도 실행 영역 가까이에 표시한다. 좁은 화면·큰 글씨에서는 영역 높이를 제한하고 내부 스크롤을 허용해 본문을 전부 가리지 않는다. 계정 변경 시 실행 영역도 숨긴다. 키보드가 열리면 실행 영역을 키보드 위로 올리고 요약을 접어 버튼을 우선한다. 당일 사진 정책·1,000P·앨범 지면·보유 사진·실제 서버 작업은 변경하지 않는다.

신규/기존 월간 앨범, 선택 변경, 중복 요청, 실패 복구, 계정 변경, 320×568/390×844 및 글자 확대를 관련 테스트로 확인한다. 현재 네이티브 캡처와 실제 코드가 근거이며 전체 앱 빌드·실기기 검증은 범위 밖이다.
