# 포인트 전체 이용내역과 필터

전체 UX 개선을 이어가는 사용자 요청에 따라, 요약용 최신 5건을 전체 이용내역으로 재사용한 문제를 고친다. 기존 잔액·충전·AI 복귀·결제 검증은 유지한다.

## 결정

- 요약은 기존 `getMyPointLedger(limit: 5)` 계약을 보존한다. 상세는 별도 `getMyPointLedgerPage(filter, before, limit: 20)`로 조회한다.
- 전체/적립/차감을 서버에서 먼저 필터링한다. 생성 시각과 ID 내림차순 커서로 이어 읽고, 1건을 추가 조회해 더 읽을 내역이 있는지 판정한다. 같은 시각의 항목과 새 거래 삽입에도 페이지 위치가 밀리지 않는다. DB 전체 시점 고정 스냅샷을 제공한다는 뜻은 아니다.
- 기존 모바일/웹 목록 아래에 `이전 내역 더 보기`를 둔다. 기존 행·잔액·필터 디자인을 유지하며, 행의 대각선 화살표는 사용자 선호에 맞게 적립 + / 차감 − / 0P 영수증 아이콘으로 바꾼다. 최초 조회 오류와 후속 조회 오류를 구분하며, 더보기 실패 시 이미 읽은 내역과 커서를 보존한다. 진행 중 중복 조회를 막는다.
- owner/filter/새로고침이 바뀌면 페이지 체인을 초기화한다. 늦은 응답과 A→B→A 계정 전환의 이전 요청은 무효화한다. 기존 적립·구매·새로고침 지점은 상세 provider도 명시적으로 무효화한다.

단순히 5를 20/100으로 늘리면 그보다 오래된 내역을 계속 잃는다. 전체 원장을 한 번에 내려받는 방법도 피한다. 기존 조회/RLS와 앱의 Riverpod 패턴을 이용한 작은 페이지 단위 조회를 택한다.

## 검증과 한계

실제 기존 화면에 최신 적립 5건과 그 이전 차감 1건을 주입해 현재 오류를 먼저 캡처한다. 저장소 실제 HTTP 요청 형태, 페이지 경계·서버 필터, 실패·재시도·중복·계정 전환을 검사한다. 모바일의 실제 번들 폰트와 작은 화면·큰 글씨를 확인한다. 실제 잔액 변경·결제·운영 DB 변경·앱 전체 빌드는 하지 않는다.
