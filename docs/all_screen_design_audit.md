- **빈 페이지 첫 행동:** 빈 편집 페이지 안에 사진 넣기와 디자인 고르기를 제공한다. 작은 캔버스에서는 두 행동을 메뉴로 보여주고, 저장 중에는 비활성화하며 읽기 전용에서는 표시하지 않는다. 실제 사진을 넣으면 안내가 사라지고 안내 문구·버튼은 문서나 인쇄 레이어에 저장되지 않는다.

별도 검수 이미지·영상·웹 릴리스 빌드·PDF 파일을 생성하지 않는다. 실제 AI 생성·로그인·결제·운영 서버 변경 없이 로컬 fixture와 자동 검사로 검증하며, 최종 결과와 재생성 가능한 검사 캐시 정리는 `docs/verification/design-priority-three-2026-10-20.json`에 기록한다.

앱 AI 검사 6개 파일의 49개를 통과했고 최종 요청 보호 변경 후 해당 흐름 파일 10개를 재확인했다(기존 9개 대체와 추가 1개로 고유 AI 검증 50개). 편집·저장·이탈·도구 창 5개 파일의 68개를 통과했으며, 반응형 실제 조작 경로를 맞춘 빈 편집 검사 15개를 다시 확인했다. 인쇄 경고·문서 연결·접근 보호 42개와 추가 보호 후 세션 검사 18개도 통과했다. 서로 중복된 실행을 합산하지 않는다. 변경 관련 29개 파일의 분석은 문제 없다. Chrome에서는 실제 좁은 캔버스의 추가 메뉴와 인쇄 화면의 스크롤을 거쳐 클릭 가능한 버튼을 조작하며, 실행별 결과와 최초 실패의 후속 해결은 위 JSON에 구분해 기록한다. 원본 미디어·기존 골든은 갱신하지 않으며 운영 배포는 수행하지 않는다.

최종 Chrome 확인 범위는 AI 대기 5개·빈 편집과 인쇄 수정 화면 15개·인쇄 경고 3개다. 처음 두 편집 검사가 작은 캔버스의 추가 메뉴를 거치지 않던 문제는 실제 동선으로 바꿔 별도 재실행했고, 인쇄 검사도 화면 안으로 버튼을 스크롤한 뒤 클릭 가능 여부를 확인하도록 맞춰 통과했다. 최종 네이티브 인쇄 화면 22개와 빈 편집 15개도 다시 통과했다. 검사 동선 수정으로 주요 기대 조건을 생략하거나 운영 소스를 우회하지 않는다.

## 2026-10-20 부분 적용 3개 마무리

- **좁은 웹 편집 패널:** 아래 속성 패널의 손잡이를 드래그하거나 확대·축소 버튼, 위아래 방향키, Home/End로 높이를 바꾼다. 화면읽기에 이름·현재 높이·조절 동작을 전달한다. 패널을 닫았다 열거나 창 방향·키보드가 바뀌어도 사용자가 정한 높이와 캔버스 배율을 유지하며, 임시 공간 부족에는 높이를 제한한다. 짧은 가로 창에서는 헤더를 압축하고 작품과 속성까지 스크롤로 접근한다.
- **첫 제작 방식별 예시:** 직접 배치, AI 구성, 기존 디자인 선택을 서로 다른 코드 기반 도형으로 보여준다. 새 사진·미리보기 자산이나 실제 AI 요청 없이 결과의 차이를 설명하며, AI의 결과 변동 안내와 실제 전달된 포인트·무료 조건을 유지한다. 앱·웹, 검색 후 축약 영역, 큰 글자에도 세 선택과 기존 이동 동작을 제공한다.
- **선택 앨범 진행 상태:** 저장된 페이지 수와 기존 목록의 완성 판정을 사용해 `3/8 페이지 진행 중`, `3 페이지 진행 중`, `완성한 앨범`을 표시한다. 보기 전용 권한도 함께 안내한다. 잠금 정보는 읽기 진입 때도 설정되므로 이를 실제 타인의 편집 활동으로 해석하지 않는다. 긴 제목·큰 글자에서 상태와 조작 버튼이 겹치지 않게 한다.

이번 마무리는 소스와 자동 검사로 검증한다. 새 검수 갤러리·영상·웹 릴리스 빌드는 만들지 않는다. 변경된 제작 화면의 기존 골든 기준 이미지 4개만 갱신하며 검사 후 재생성 가능한 임시 캐시를 삭제한다. 최종 실행 결과와 소스 지문은 `docs/verification/design-completion-2026-10-20.json`에 기록한다. 아래의 이전 검수 폴더와 캡처·릴리스 빌드 기록은 당시 결과다.

검증은 홈·제작 흐름 109개, 웹 작업공간 26개, 뷰포트 9개, 신규 제작 예시 8개가 통과했다. 최종 상태 문구 정리 후 홈 71개를 다시 확인했고, 마지막 정렬 수정 후 신규 예시 8개를 재확인했다. 실제 Chrome의 작업공간·제작 예시 34개, 기존 제작 기능·골든 비교 8개도 통과했다. 중복 실행을 고유 검사 수로 합산하지 않는다. 변경 관련 7개 파일의 최종 분석은 문제 없으며, 320·390·844 폭의 기존 기준 이미지를 직접 확인했다. Chrome의 비이미지 구조 검사는 골든 전용 폰트 로딩을 기다리지 않으며 모든 테스트 본문을 실행한다. 네이티브에서는 실제 번들 폰트 검증을 유지한다.

## 2026-10-20 우선순위 기반 앱·웹 개선

이 단계의 구현과 당시 검수 기록은 아래 변경과 `output/design-improvements-2026-10-20/verification.json`에 남겼다. 현재 소스의 후속 변경은 위 마무리 절과 별도 실행 기록을 따른다. 삭제된 캡처와 이전 검사 횟수를 최신 소스의 증빙으로 혼용하지 않는다.

### 높은 우선순위

- 주요 버튼은 공통 `onAccent`를 사용한다. 앱 청록 배경과 글자의 대비를 약 2.86:1에서 4.51:1로 높였으며, 별도 PrimaryActionButton도 현재 테마의 주요 버튼 색을 따른다. 큰 글자에서는 최소 높이를 유지하며 버튼 높이가 늘어난다.
- 사진을 채우는 단계는 사진 추가가 주요 행동이다. 나중에 채우기는 보조 행동이며, 충분히 채운 뒤 표지 확인으로 진행한다. 좁은 폭·큰 글자에서는 버튼을 세로로 배치한다.
- 책으로 만들기 → 인쇄 검토 → 배송지 → 주문 확인으로 안내한다. 아직 수정할 수 있는 단계의 잠금·확정 표현을 제거하고 모바일의 중복 완성 화면을 생략한다. 취소·이어서 편집·기존 주문 가능 상태는 보존한다.
- 좁은 웹의 속성을 캔버스 아래, 중간 폭에서는 옆으로 배치한다. 작품 위를 덮지 않으며 짧은 창·키보드·페이지 목록에서는 작품 영역을 확보한 채 스크롤한다. 패널 변경 시 확대 배율을 유지한다.

### 탐색과 제작 구조

- 앱 메뉴는 내 앨범 / 스토어 / 내 디자인 / 마이이며 기존 목적지 ID를 유지한다. 기존 책 무대·실물 비율은 유지하고 선택한 앨범 제목을 표시한다.
- 첫 제작에는 직접 만들기·AI·템플릿 각각의 결과 설명과 실제 전달된 AI 포인트·무료 조건·쪽수에 따른 변동 안내를 제공한다. AI 요청·조건 확인·생성·결과 검토의 보조 진행 단계를 표시한다.
- 웹 첫 방문자는 공개 디자인을 둘러보고 사용 시 로그인한다. 로그인 이후에는 내 앨범 작업공간에서 이어간다. 공개 상세는 읽기 전용이며 구매·소유권 조회나 계정·고객 문서 생성 없이 공개 번들 디자인만 보여준다.
- 로그인 후 선택 디자인으로 돌아온다. 앱은 공개 ID만 메모리에 보관하고 한 번 소비한다. 웹은 정규 내부 경로의 15분 복귀 기록과 저장 실패 시 탭 메모리를 사용한다. 계정 변경·오래된 콜백·유효하지 않은 ID·프로필 검증 전 접근을 차단한다.
- 일반 웹 헤더는 넓은 창에서 탐색을 같은 줄에, 좁은 창·큰 글자에서는 전체 메뉴에 배치한다. 카탈로그의 보조 필터·정렬은 작은 창에서 접고 검색은 한 진입점으로 정리한다.
- 앱 편집은 사진·글·템플릿·꾸미기를 먼저 두고 구조 도구를 구분한다. 웹은 사진 교체·자르기·글 편집의 이름을 보여주며 수치는 접힌 고급 조정으로 제공한다.
- 계정 저장과 이 브라우저 임시 보관을 구분하고 실제로 확인한 저장 시각만 표시한다. 키보드로 템플릿 카드에 접근·선택할 수 있으며 포커스와 선택 상태를 제공한다. 동작 줄이기에서는 책 진입의 자동 이동도 생략한다.
- 모바일 소재 검색의 입력란이 빠지던 조건을 수정했다. 문의 폼은 낮은 키보드 공간에서 입력란을 확보하면서 최대 글자 수 검증을 유지한다.

### 관리자 웹

주문·섹션·상태 필터·목록 페이지의 주소 복원, 브라우저 뒤로가기와 이동 잠금, 늦은 상세 응답 취소, 대시보드 영역별 실패·재시도를 연결했다. 보조 글자 대비와 작은 화면 메뉴도 보완했다. 고객 검색어·수령인·로그인 정보는 주소에 저장하지 않는다.

### 검수 범위와 자료

새 자료는 현재 생산 위젯과 공개 번들 작품, 로컬 계정·주문 fixture로 만든다. 운영 사용자의 사진·로그인·결제·인쇄 발주를 실행한 증빙이 아니다. 실제 책 표지·내지 원본, 저장 문서 좌표, 서버 가격·소유권·결제 계약은 변경하지 않는다. 세부 검사 결과와 현재 소스·캡처 해시는 검수 폴더의 `verification.json`에 기록한다.

최종 변경 소스 분석과 앱·웹·관리자 회귀 검증을 마쳤다. Chrome 14개 통과·기존 네이티브 전용 1개 제외, 관리자 31개 통과를 확인했다. 표준 JavaScript 웹 릴리스 빌드가 성공했고, 실제 좁은 브라우저에서 공개 탐색 → 디자인 상세 → 로그인 → 뒤로가기를 확인했다. 기존 웹 저장 플러그인의 선택적 WebAssembly 호환성 경고는 빌드 기록에 남겼다. 이 단계의 캡처 38장 중 2장은 완성된 웹 빌드의 실제 로컬 브라우저 화면이다. 아래 후속 검수에서 4장을 추가해 현재 자료는 42장이다.


### 이어서 진행한 흐름·접근성 보완

- 스토어 탭과 `/designs`·`/designs/materials` 주소를 연결한다. 같은 작업공간에서 탭을 바꾸고 브라우저 뒤로가기·앞으로가기로 복원하므로 두 카탈로그의 검색·필터·스크롤을 보존한다. 새로고침은 주소에 해당하는 탭을 열며 검색어는 URL이나 로그인 복귀 기록에 저장하지 않는다. 다른 화면·대화상자·편집기의 이탈 보호를 통과시키지 않는다.
- 비로그인 디자인 상세·사용 소재에서는 계정용 전역 메뉴·알림·보관 동작을 숨기고 로그인 진입을 명확히 한다. 공개 디자인 공유는 정식 공개 ID의 상세 링크를 포함하고 OAuth 정보·현재 쿼리·사용자 정보를 제외한다. 웹은 현재 설치 주소를 사용하며 앱은 `PUBLIC_WEBSITE_URL` 설정 또는 기존 Firebase Hosting 주소를 사용한다. 실제 공개 호스팅에는 새 빌드의 별도 반영이 필요하다.
- 공개 디자인 검색에는 입력 지우기와 검색 완료·스크롤 시 키보드 닫기를 제공하고, 큰 글자의 카드 설명에 필요한 높이를 확보한다.

## 우선 해결할 문제

### 1. 완성 확인 화면: 가로에서 안내와 버튼이 잘림

근거: `album_frozen_screen.dart`의 `_buildAlbumCard`는 앨범 인자를 사용하지

- 실제 완성한 표지를 원래 비율로 보여 주고 FREEZE 배지/별빛/임시 모형을 제거.
- 가로는 표지와 완료 정보/작업을 나누고, 세로는 안전 영역 안의 자연스러운 완료 구성.

### 2. 다크 대비: 알림 제목·마이 닉네임·잔액이 거의 안 보임

근거: `notification_screen.dart`의 제목/행과
`my_point_balance_card.dart:35`, `my_page_screen.dart`의 프로필 제목은

글자가 검정 바탕에 남는다. 새 캡처에서 확인했다.

- 화면 배경과 헤더, 제목, 요약, 구분선에 같은 테마 인식 규칙 적용.
- 사진/인쇄 종이/앨범 무대는 의도된 밝은 표면을 유지. 모든 흰색을 일괄 반전하지 않음.

- 문의/포인트/스토어 같은 흰색 고정 화면의 일부 아이콘·시트도 같은 기준으로 후속 점검.

### 3. 주문 상세: 저장된 책 규격과 다른 규격을 표시

근거: `order_history_screen.dart:423`은 주문 상품과 무관하게
`200×200mm 소프트커버`를 붙인다. 검토 주문의 저장된 규격은
`REDP_250X200_SOFT`, 250×200mm지만 상세에는 200×200mm가 나온다.

- `order.printProductLabel` 등 이미 있는 저장 스냅샷 기반 표시 사용.
- 규격을 모르면 모른다고 표시하며 임의의 정사각형으로 대체하지 않음.
- 상세 시트는 고정 글자 크기, 제한 너비, 충분한 높이와 스크롤로 구성.
- 결제/제작/배송/수령 정보를 그룹화하고 복사 버튼은 좁을 때 줄바꿈 허용.

## 구현 순서

1. 완성 확인 가로 배치, 알림/마이 다크 대비, 주문 상세 규격 표시를 먼저 수정.
2. 실제 앨범 중심의 완성 확인과 초대 화면을 정돈. 링크 준비/실패/권한을 함께 설계.
3. 인쇄 미리보기와 주문 상세를 책 중심·검수 중심 화면으로 구성.
4. 나의 기록/공유 목록과 작은 선택 시트를 현재 스타일로 통일.
5. 구매 확인/완료, 약관/문의, 접힌 마이 정보를 정돈. 포함 소재 재사용 정책은 서버와 함께 구현.

## 2026-10-15 스토어 큐레이션 개편

- 이전 큰 회색 무대/미니 표지 선택 목록을 실제 표지 중심 가로 스냅 컬렉션으로 교체. 세로는 큰 표지 아래 정보, 가로는 표지 옆 정보. 소재는 더 낮고 작은 가로 선반으로 분리.
- 홈과 리더의 책 디자인, 크기, 비율, 떠있는 움직임은 이번 작업에서 수정하지 않음. 템플릿·소재 가격과 보유 정책도 변경하지 않음.
- `store_curations` 두 설정(templates/materials)을 읽고 관리자 지정 순서를 유지. 누락/비활성 상품은 대신 임의 상품을 채우지 않고 제외. 숨김/빈 설정도 캐시하여 네트워크 실패 때 기본 홍보가 되살아나지 않도록 검증.
- 별도 SnapFitAdmin에 `스토어 큐레이션` 메뉴: 제목, 소개, 켜기/끄기, 판매 상품 검색/선택, 순서, 제외, 저장, 취소, 미리보기. 버전 비교로 동시 편집 덮어쓰기 방지. 관리자 권한 확인 뒤에만 서버 클라이언트 생성.
- SnapFit 실서버에 이번 마이그레이션과 `store-curation-admin`만 분리 배포. public SELECT 허용, 고객 UPDATE/RPC 금지, 서비스 전용 RPC 허용, 초기 선택 상품 8종 모두 판매 중임을 재조회. 비인증 HTTP 요청 401 확인.
