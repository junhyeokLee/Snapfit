# SnapFit 고객 화면 재설계

## 2026-10-14 내 보관함 · 다시 찾기 개선

- 홈/리더를 변경하지 않고 구매한 템플릿과 소재를 찾는 보관함만 정리한다.
  템플릿 표지는 기존 공용 책 표면을 사용해 B형 책등의 사진 곡면·제본 홈·
  그림자를 적용한다. 목록에서는 지속 애니메이션 없이 정적인 책으로 보여 준다.
- 캐시된 표지는 660px 썸네일을 그대로 사용하고 전체 템플릿 문서나 내지를
  생성하지 않는다. 새 옵션은 보관함에서만 켜며 다른 목록의 기본 동작은 유지한다.
  사용자/원격 문서는 원래 캔버스와 사진·문구 배치를 유지한다.
- 세로는 구매한 항목/즐겨찾기, 유형, 접이식 검색을 유지한다. 가로는 184px
  분류 영역과 독립 스크롤 목록을 나누어 항목 하단의 구매 표시·북마크가 잘리지
  않게 한다. 시스템 안전 영역과 글자 확대를 반영하고 고정 크기 타이포를 쓴다.
- 구매 목록은 즐겨찾기 먼저, 즐겨찾기 목록은 최근 즐겨찾기순이 기본이다.
  이름순을 별도로 제공하며 확인할 수 없는 구매 시각으로 최신 구매순을 만들지
  않는다. 검색·분류·정렬은 회전 후 유지하고 변경 시 지연 표시를 12개로 초기화한다.
- 실제 소유 상품 키로 구매 목록을 제한한다. 유료 템플릿에 가격 정보가 없으면
  즐겨찾기 목록에서 판매 준비 중으로 표시하고 무료라고 추정하지 않는다.
  포함 소재 지급·구매 권한·상품 가격·편집 문서·인쇄 데이터는 바꾸지 않는다.
- 같은 `output/account-library-qa/index.html`에 실제 위젯의 세로/가로·
  라이트/다크 캡처와 이름순 상태를 반영한다. 기기 설치와 운영 구매는 하지 않는다.
- 검증: 관련 14개 파일의 232개 테스트 통과, 변경한 Dart 4개 파일 정적 분석
  문제 없음. 캐시 표지는 전체 문서를 읽지 않고, 비정사각 캔버스 비율·1.5배
  글자·회전 유지·검색·정렬·지연 표시·기존 소유권 필터를 회귀 검증했다.

## 2026-10-14 편집기 페이지 목록 · 레이어 정리 적용

- 홈/리더와 앨범 캔버스·페이지 넘김 연출은 변경하지 않는다. 편집기의 주변
  목록과 도구 패널만 스토어/제작 화면의 선·타이포·선택 색에 맞춘다.
- 페이지 썸네일은 선택 전후 크기를 유지하고 사진 위의 삭제 뱃지·선택 광택을
  제거한다. 쪽 추가/삭제는 별도 44px 이상 도구로 분리한다. 기존 표지 보호,
  2쪽 추가와 최대 80쪽 규칙·삭제 확인·쪽 이동 콜백을 그대로 사용한다.
- 목록은 지연 생성하며 먼 쪽 선택·추가·회전 시 현재 쪽을 자동으로 보여 준다.
  원본 `CoverLayout`/내지 렌더러와 배경색을 유지하고 목록만 바꾼다.
- 레이어 시트는 사진·문구 글꼴·스튜디오 장식의 실제 미리보기, 유형과 선택
  상태를 보여 준다. 가로 패널은 고정 크기 타이포와 아이콘을 쓰고, 좁은
  레이어 항목은 이름과 드래그 손잡이를 나누어 배치한다.
- 인라인 레이어 선택은 편집 화면을 pop하지 않는다. 모달 선택만 시트를 닫는다.
  순서 이동은 기존 `updatePageLayers`/`syncZOrder` 및 실행 취소로 연결한다.
- 레이어 ID가 같아도 사진·문구 교체를 갱신하며 가변 목록 변경도 감지한다.
  기기 사진 썸네일은 레이어/asset ID를 함께 키로 사용하고 제거된 항목은 정리한다.
  번들 이미지는 로컬 에셋, 원격 이미지는 기존 공용 캐시를 사용하며 디코딩을 제한한다.
- 같은 `output/editor-flow-qa/index.html`에 실제 편집 위젯의 세로/가로,
  라이트/다크 캡처를 추가한다. 반복 페이지는 테스트 fixture로, 새 템플릿이 아니다.
  기기 설치·운영 API·구매·저장은 이 디자인 검증과 구분한다.
- 기존 편집기 기준 이미지 두 개를 `before-editor-*`로 보존한다. 테스트에서는
  물리 기기 크기와 렌더링 크기를 일치시키고 실제 앱 글꼴을 로드해 방향·글자
  표시를 검증한다. 홈/리더 또는 다른 화면의 기준 이미지는 갱신하지 않는다.
- 최종 검증: 관련 13개 테스트 파일의 492개 테스트 통과, 변경 대상 6개 Dart
  파일 정적 분석 문제 없음. 실제 편집 위젯의 가로/세로·라이트/다크 캡처
  12개를 확인했으며, 1.5배 글자·80쪽 목록·회전 유지·실제 터치/드래그·
  사진 교체·빈 상태·실행 취소·저장 경로를 포함한다. 실기기 설치는 하지 않았다.

## 기존 고객 화면 시안

아래 단계는 디자인 시안이며 운영 결제나 소재 소유권을 변경하지 않는다.
기준 화면은 현재 홈, 앨범 리더, 편집기다. 사진·앨범을 중심에 두고
흰색/연회색 여백, 차분한 검정 타이포, 브랜드 시안 #08B8D0를 사용한다.
큰 라운드 컨테이너의 중첩, 과장된 혜택 문구, 기능 설명용 히어로를 줄인다.

## 포함 소재 구매 정책 설계

현재: 템플릿 문서에 배치된 소재는 사용할 수 있으나 별도 소재 소유권을 지급하지 않는다.
목표: 템플릿 구매 시 공개한 구성품 목록의 재사용 가능한 소재도 계정 보관함에 지급한다.

- 상세: 총 구성품, 실제 이미지, 이름, 유형, 보유 여부를 구매 전에 노출한다.
- 구매 확인: 템플릿 가격, 포함 소재, 새로 추가되는 항목, 구매 후 잔액을 확인한다.
- 구매 완료: 템플릿으로 시작하기와 받은 소재 보기 두 경로를 제공한다.
- 보관함: 템플릿/스티커/프레임/문구/종이를 구분하고 즐겨찾기를 먼저 정렬한다.
- 다른 앨범에서도 소재를 재사용할 수 있다. 외부 원본 재배포 권한과는 구분한다.
- 보유 소재는 중복 지급/차감하지 않는다. 템플릿 고유 편집 디자인은 별도 상품이므로
  보유 소재에 따른 자동 가격 차감은 적용하지 않는 안으로 설계한다.
- 무료 소재도 구성품에 표시하되 유료 혜택으로 부풀리지 않는다.
- 일반 텍스트 레이어와 문구 스타일 상품은 다르다. 저장 가능한 문구 스타일만 상품으로 센다.
- 기존 구매자도 해당 구매 당시 제공 범위에 맞게 소급 지급하는 방향으로 구현한다.
- 지급 목록은 서버가 관리하는 상품 구성표를 기준으로 하며 사용자 편집 JSON은 권한 근거로 쓰지 않는다.
- 결제와 소재 지급은 한 트랜잭션에서 처리하고 재시도 시 이중 지급/차감하지 않는다.
- 환불, 상품 판매 중단, 소재 추가 개정은 기존 구매 이력과 구성표 버전을 함께 다룬다.

## 디자인 검증

- 정사각/세로/가로 앨범의 원래 비율 유지. 템플릿 종류를 기기 비율과 혼동하지 않는다.
- 모바일은 한 열과 하단 주요 작업, 넓은 화면은 미리보기와 정보의 두 영역을 사용한다.
- 상세의 소재 갤러리는 원본 투명 PNG를 보여준다. 임의 아이콘으로 대체하지 않는다.
- 뒤로가기, 즐겨찾기, 검색, 필터, 구성품 확인, 구매 취소/부족잔액 상태를 포함한다.
- 시안의 샘플 주문/잔액/소유권은 실제 사용자 데이터가 아니며 결제하지 않는다.

단일 시안 파일: `../designs/snapfit-experience-design.html`.
이 파일을 계속 수정하며 승인된 영역부터 Flutter로 구현한다.

## Flutter 적용 1차

- 스토어: 상단 대형 추천 캐러셀을 제거해 검색과 카테고리, 실제 템플릿 그리드를 먼저 노출한다. 카드의 큰 라운드와 외곽 그림자를 줄인다.
- 상세: 겹친 세 표지 대신 원본 비율을 유지한 단일 표지 무대를 사용한다. 표지 탭의 전체 미리보기, 구매와 분량 선택은 유지한다.
- 마이: 큰 그라데이션 프로필 카드를 사진/계정 정보의 행으로 바꾸고 메뉴 아이콘과 터치 간격을 정리한다. 포인트, 주문, 저장 공간, 관리자와 계정 동작은 유지한다.
- 홈/리더/편집은 수정하지 않는다.
- 소재 개별 소유권 지급, 새 보관함, 충전/주문/생성 하위 화면 전체의 디자인 전환은 아직 미적용이다. HTML의 샘플 구매 안내를 실제 지급 기능처럼 사용하지 않는다.

## 시안 구조 적용 2차

1차는 기존 UI의 스타일 수정에 그쳐 승인된 시안과 차이가 컸다. 아래 영역은 시안 구조로 교체한다.

- 스토어: SnapFit 헤더, 원문 제목, 검색, 가로 밑줄 탭, 2열 표지 무대, 북마크. 실제 51종 문서/가격/즐겨찾기 연결.
- 상세: 규격별 표지 무대, 규격 선택, 왼쪽 정렬 정보, 소재 미리보기/목록, 실제 내지, 작은 하단 CTA. 구매와 생성 로직 유지.
- 마이: 작은 프로필, 회색 포인트 요약, 구분선 메뉴. 계정/저장 공간/운영 기능은 추가 설정에 보존.
- 포인트: 실제 스토어 상품과 가격을 행으로 나열, 구매 복원과 서버 이용 내역 유지.
- 알림 설정/문의/정책 목록/주문 목록/알림 목록: 흰색 바탕, 동일 타이포 및 평면 목록으로 적용.
- 홈 이외 탭: 흰색 아이콘 내비게이션. 기존 5개 목적지를 유지하며 홈에서는 기존 검은 바/앨범 무대를 그대로 사용.
- 보관함: 실제 서버 소유 템플릿만 필터링하며 로딩/오류를 빈 보관함으로 표시하지 않는다.

아직 미완료: 소재별 보관함 탭과 서버 번들 지급, 별도 구매완료 화면, 생성 단계 전체, 로그인/스플래시, 인쇄 상세와 주문 상세의 완전한 시안 정합성. 이 영역을 적용 완료로 간주하지 않는다.

## 상단/하단 정합성 적용 3차

- 홈은 기존 디자인을 유지한다. 홈 이외 주 메뉴는 시안 그대로 스토어/소재/보관함/마이 4항목이며, 알림은 상단 벨로 이동한다.
- 모바일 헤더 60, 하단 68에 시스템 안전 영역을 별도로 더한다. Lucide 0.468.0 원본 아이콘, 선 두께 1.6, 21 크기와 10 크기 메뉴 라벨을 사용한다.
- 소재 화면은 실제 스티커/프레임/문구/종이 카탈로그, 즐겨찾기와 기존 구매 권한 확인을 연결한다.
- 보관함은 서버에서 확인한 개별 구매 상품만 표시하며 소재 유형별로 나눈다. 템플릿 구매에 따른 소재 자동 지급은 여전히 미구현이며 보유로 추정하지 않는다.
- 상세/마이/알림/주문/약관 화면 상단도 공통 헤더를 사용한다.
- 생성 단계, 로그인/스플래시, 인쇄/주문 상세 전체의 시안 전환은 후속 범위로 남아 있다.

## 스토어 탐색 성능 보완

홈/리더/편집의 완성된 그래픽과 페이지 넘김은 후속 개편 기준점으로 유지한다. 신규 입력을 많이 넣는 것보다 안내, 인증 복구, 실제 상태의 일관성을 먼저 완성한다.

## 템플릿 상세의 책 표현과 이용 범위 (2026-10-14)

- 승인한 B형 홈은 수정하지 않는다. 상세 표지는 기존 `HomeCoverFrame`,
  `AlbumSpineImage`를 사용해 같은 곡면 사진, 제본 홈, 얇은 단면과 그림자를 표시한다.
  원본 템플릿 레이어, 사진 크롭, 규격, 편집 및 인쇄 데이터는 유지한다.
- 내지는 실제 1-2, 3-4쪽 순서의 좌우 펼침면으로 연결한다. 남은 마지막 쪽은
  한 장만 표시하고 빈 상대 페이지를 만들지 않는다. 제본 명암은 좁은 중앙 영역에만
  적용한다. 각 쪽을 누르면 그 쪽을 기존 전체 보기에서 확인할 수 있다.

  선택 상태를 사용하며, 지원하는 원본 규격별 좌표계를 그대로 렌더링한다.
