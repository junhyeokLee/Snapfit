# 통합 앨범 편집 흐름 — 설계와 구현 기준

2026-11-11. 사용자는 기존 프로토타입의 사진 채우기 단계를 반드시 유지할 필요가 없다고 했고, 독립 사진/표지 단계를 줄인 통합 편집 방향에 동의했다. 초기 시안은 사용자가 제외했고, 후속 승인으로 기존 편집기 UI를 유지한 진입 단축과 선택 사진 도구를 구현하는 범위로 전환했다. 서버·DB·배포는 변경하지 않는다.

## 최신 사용자 피드백 — 새 편집기 시안 제외

사용자는 표시한3개 시안이 별로이며 기존 편집기가 더 낫다고 피드백했다. 세 이미지는 구현 기준에서 제외한다. 통합 편집으로 진입 단계를 줄이는 방향과 편집기 자체를 새로 디자인하는 작업을 구분한다.

- 기존 PageEditorScreen은 이미 표지와 내지를 모두 편집한다. 사용자에게 필요한 변화는 여기에 도달하기 전에 사진 채우기/별도 표지 편집을 거치는 과정을 줄이는 것이다.
- 다음 제안의 기준은 기존 편집기 UI다. 상단 페이지 썸네일, 큰 편집 캔버스, 대상에 따라 바뀌는 도구, 재배치·더보기·undo/redo를 보존한다.
- 추가 사진/순서 배치는 선택 도구로 연결한다. 큰 상시 사진 패널로 캔버스를 밀어내지 않는다.
- 기존 UI를 보존하는 진입 흐름으로 범위를 좁힌다. 생성 attempt·ID/초안 연결·실패 복구는 같은 계약을 유지해야 한다.
- 후속 사용자가 실제 적용과 다음 화면 점검을 승인했다. 현재 실행 범위와 검증 기록은 `docs/superpowers/plans/2026-11-11-unified-album-entry.md`를 따른다.

## 승인된 방향

디자인 선택 → 간단한 앨범 설정 → 표지·내지 통합 편집 → 저장.

- 필수 사진 채우기 화면과 별도 표지 편집 단계를 없앤다.
- 실제 선택한 디자인의 표지·내지를 적용한 채 전체 편집기를 연다. 표지/내지를 고치는 순서를 강제하지 않는다.
- 사진 여러 장 추가와 빈 슬롯 순차 배치는 편집기 안의 선택 도구로 둔다. 미리보기·취소·기존 사진 보존과 도구 안의 순차 배치 되돌리기를 유지한다. 편집기에 적용하면 변경된 각 페이지에 기존 undo 기록을 한 번씩 남긴다.
- 사진·글 수정·페이지 이동을 먼저 보여주고 자세한 꾸미기·배경·레이아웃·레이어 순서는 요청 시 연다.
- 소프트/하드커버를 주문 단계에서 선택하는 방향은 별도 주문 흐름 확인 후 구체화한다. 이번 구현은 선택 기능을 잃지 않도록 기존 설정의 커버 선택을 유지한다.
- 월별 기록과 포인트 등 홈의 리텐션 기능은 이번 앨범 제작 화면에 넣지 않는다.

## 이번 시안의 기본값 — 제안

- 한국어 모바일 390×844. 기존 밝은 종이/회색 바탕, 청록색 선택과 저장 버튼, Noto 계열 UI를 이어간다.
- 예시 앨범은 공개 웨딩 디자인(-9501)의 표지와 내지24쪽이다. 표지·사진·레터링 원래 비율을 유지한다. 실제 사용자 사진을 쓰지 않는다.
- 기존 편집기와 같은 수동 `저장`을 사용한다. 아직 구현하지 않은 자동저장 완료·공유 완료·앨범 완성 상태를 꾸미지 않는다.
- 사진이나 글을 누르면 대상에 맞는 도구를 보여준다. 선택 해제·사진 구도·글 수정·undo/redo는 숨기지 않는다.
- 초기 설정의 이름50자, 공식5규격, 내지20~80쪽/2쪽 단위와 실제 콘텐츠 최소값은 보존한다. 기본값을 채운 짧은 설정으로 제안한다.
- 대각선 화살표·과한 텍스트·카드 중첩·사진 늘임·기기 테두리 없음. 작은 글자라도 터치 영역은 최소48px.

## 확인된 코드 제약

- 전체 편집기는 이미 표지(EditCover)와 내지(PageEditorCanvas), 사진·글·레이아웃 편집을 지원한다.
- 실제 모바일 기본 도구는 EditorContextDock이며 선택 대상별로 바뀐다. EditorBottomMenu는 주로 가로 화면이다.
- 구현 전 사진 채우기의 미배치 대기 목록은 편집기 인자가 아니었다. 현재 `initialPhotoFillSession`의 독립 스냅샷으로 인계하고, 연결된 생성 초안의 checkpoint와 함께 남은 목록을 기록한다.
- 현재 저장은 앨범ID와 연결된 임시 저장을 전제로 한다. 표지 화면에 묶인 생성 attempt/중복 생성 방지/ID와 초안의 내구성 있는 연결을 UI와 분리해 재사용해야 한다.
- 단순히 PageEditorScreen으로 push하는 우회는 하지 않는다. 부모의 표지 문구·규격 variant·추가 빈 페이지·상품키·소유권·현재 편집 문서 보존을 함께 설계한다.
- 정상 생성 경로는 이미 초대 화면을 필수로 거치지 않는다. 남은 legacy case2와 현재 동작을 혼동하지 않는다.
- 사진 없는 상태도 편집은 가능하다. 저장·주문 완성 조건은 같은 것으로 취급하지 않으며 주문 검수는 별개다.

## 시각 비교 범위

세 개의 독립 방향을 이미지로 비교하고 사용자가 고른 방향을 구현 기준으로 삼는다. 기존 실제 화면 캡처를 시안에 첨부한다. 캡처는 테스트용 소유자·번들 사진·실제 편집 위젯으로 수행하며 운영 개인 앨범·저장 성공·실기기 전체 앱 검증으로 보고하지 않는다.

## 이번 실제 소스 캡처

`docs/verification/unified-editor-design-2026-11-11/`의 01-cover, 02-inner-page, 03-selected-photo-tools, 04-page-rail-landscape. 기존 PageEditorScreen을 실제 템플릿·실제 폰트·로컬 테스트 세션/동기 가짜 소유자와 기존 저장소 대역으로 캡처했다. 실행4개 통과, 실패0개. 앨범ID가 없는 로컬 세션임을 확인했고 사용자 앨범·갤러리·저장·운영 API는 실행하지 않았다. 전체 앱 빌드/실기기/브라우저 검증이 아니다.

직접 확인한 표지·내지·사진 도구 중 01/03과 이전 설정 화면의 실제 PNG를 세 Image Gen 호출 모두에 첨부했다. 생성된 UI는 제안이므로 실제 표지/사진/상품 문서·48px 터치 영역·주문 규격·접근성·저장 복구 구현을 대신 증명하지 않는다.

위3개 생성 결과는 최신 사용자 피드백으로 구현 기준에서 제외했다. 기존 편집기를 시각 기준으로 유지하며, 후속 실행에서는 설정 진입 경로와 선택 도구만 변경한다. 전체 앱 빌드·운영 API·배포 없이 네이티브 위젯과 저장소 대역으로 검증한다.
