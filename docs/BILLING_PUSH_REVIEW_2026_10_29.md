휴대폰 연결이 불가능하다는 사용자 지시를 유지한다. 실제 고객 결제, 포인트 지급, 댓글·알림 생성 또는 테스트 푸시를 운영 고객에게 수행하지 않았다. 서버 키의 값은 출력하거나 문서에 저장하지 않았다.

## 보완한 동작

- 충전 진행과 영수증 처리를 분리해 과거 구매·다른 상품·다른 계정의 응답이 새 충전을 종료하지 못한다. 미완료 영수증은 지급·스토어 완료 확인 전까지 안전하게 보관한다.
- iOS 계정 UUID를 정규화한다. SK1 취소·오류 거래의 완료 처리에도 30초 상한을 적용한다.
- 실제 Android SDK가 상품·거래 식별정보 없는 취소/오류를 보내면 취소로 단정하지 않는다. 안내를 표시하고 해당 거래 결과 또는 기존 2분 watchdog 이후 구매 복원으로 확인한다.
- 웹은 결제창 성공만으로 지급을 표시하지 않는다. 서버 상태와 같은 결제 ID를 확인하며, 늦은 SDK 응답·오래된 내역이 최신 상태나 새 결제를 덮지 못한다. 지급 이후의 부분 취소는 REVIEW로 표시한다.
- 이전 웹 SDK Promise가 끝나지 않으면 새 결제 준비 전 차단한다. 공급자의 전역 창 정리 동작 때문에 화면의 잠금만 풀고 새 창을 여는 것은 안전하지 않다. 이전 창 닫기·새로고침 안내로 복구한다.
- 알림 설정을 필드별로 저장한다. 다른 기기의 수신 거부를 전체 스냅샷으로 덮지 않으며, 원격 조회 실패 시 과거 설정을 편집 가능한 최신값처럼 표시하지 않는다.
- 새 공개 댓글만 일반 문구로 알린다. 본문·사진을 복사하지 않으며 자기 댓글, 차단, 비공개·운영 제한·비활성 계정을 제외한다. 과거 댓글은 소급 생성하지 않는다.
- 푸시 전송 직전 DB 잠금·lease·기기 소유권·최신 수신 설정·현재 공개 상태를 확인한다. DB가 최신 야간 설정으로 만료 시각을 결정하며 응답 지연을 차감한다.
- 늦은 이전 계정 로그아웃이 새 계정의 토큰을 삭제하지 못하게 실제 SDK 변경 완료와 등록 순서를 보호한다.
- 포인트/결제 금액을 구분하고 확인 중·오류·재시도 안내를 정리했다. 알림함은 읽지 않은 표시·행 이동·권한 거부·연결 안 됨·전체 끄기를 구분한다.

## 보장 범위

FCM의 요청 수락이나 빈 큐 작업 성공은 실제 기기 수신 증거가 아니다. 이미 수락된 OS 알림을 서버에서 회수할 수 없고, 응답 유실 후 재시도의 정확히 한 번 도착도 보장하지 않는다. 야간 설정은 새 요청과 대기·유효 기간을 제한하지만 이미 OS에 표시된 알림의 시각을 통제하지 않는다. 금융 동작은 별도의 실제 스토어·결제사 테스트를 거쳐야 출시 준비 완료로 판단한다.

운영 반영 전후 지갑·거래 내역·상품 소유권의 전체 행 해시가 일치했다. 기존 앨범 수와 구매 건수도 유지됐다. 기존 보안 진단 건수는 동일하며 이번 변경으로 일반 사용자에게 지급/전송 RPC 권한을 추가하지 않았다.
