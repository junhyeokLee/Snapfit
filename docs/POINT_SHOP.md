# 디지털 포인트 상점 구현·운영 안내

2026-09-08 기준 코드의 동작과 운영 절차입니다. 이 문서 작성에서는 원격 변경이나 실제 결제를 수행하지 않았습니다. 서버 적용 결과와 스토어 설정 상태는 [배포 현황](PAYMENT_PUSH_DEPLOYMENT_STATUS.md)을 기준으로 확인합니다.

## 판매 범위와 소유권

템플릿·스티커·문구·사진 프레임을 보유 포인트로 한 번 구매하면 해당 SnapFit 계정에 기간 제한 없이 소유권이 기록됩니다. 같은 계정은 다른 앨범과 기기에서도 재구매 없이 사용할 수 있습니다. 판매 중지나 가격 변경 후에도 기존 구매자의 이용 권한은 유지됩니다. 계정 삭제 시 소유권도 삭제되며, 다른 계정으로 이전하는 기능은 없습니다.

상품별 가격은 운영자가 직접 정합니다. 임의의 유료 가격을 초기 데이터로 넣지 않습니다. 공개된 기존 자산은 상품 설정 행이 없으면 무료로 유지합니다.

| 서버 상품 상태 | 미구매 사용자 | 기존 구매자 |
| --- | --- | --- |
| 상품 행 없음 | 무료 이용 | 정상 운영에서는 구매 이력이 있는 상품 행을 삭제할 수 없음 |
| 판매 활성화, 가격 0P | 무료 이용 | 계속 이용 |
| 판매 활성화, 양수 가격 | 가격 확인·구매 동의 후 이용 | 추가 차감 없이 이용 |
| 가격 미설정 또는 판매 비활성화 | 판매 준비 중, 새 적용 차단 | 계속 이용 |

**상품을 등록하지 않은 상태와, 등록한 뒤 가격을 비워 둔 상태는 다릅니다.** 미등록은 기존 무료 이용을 유지하지만, 가격 미설정으로 저장하면 해당 상품의 신규 이용이 중지됩니다. 0P 상품도 무료 공개하려면 판매를 활성화해야 합니다.

무료 이용은 유료 소유권이나 차감 원장을 만들지 않습니다. 나중에 유료로 전환하면 이후 새 적용 시 구매가 필요합니다. 기존 앨범을 일괄 수정하거나 이미 배치한 자산을 삭제하는 작업은 없습니다.

## 앱에서의 이용 흐름

- 스토어 템플릿 상세와 편집기에서 미리보기·즐겨찾기는 계속 사용할 수 있습니다. 실제 사용·삽입·적용 직전에 서버의 가격과 소유 여부를 확인합니다.
- 카드에는 가능한 공간에서 `무료`, 가격, `구매 완료`, `판매 준비 중`을 표시합니다. 로딩·조회 실패는 각각 `가격 확인 중`, `가격 확인 필요`로 표시합니다. 화면에 보이는 가격만으로 구매를 승인하지 않습니다.
- 유료 미구매 상품은 로그인 후 상품명·가격·잔액을 확인하고 구매합니다. 취소·조회 실패·구매 실패 시 자산이 적용되지 않습니다. 결제창이 열린 동안 중복 요청을 막습니다.
- 잔액이 부족하면 `포인트 충전`으로 이동합니다. 돌아온 뒤 잔액·가격·소유 여부를 다시 조회하고 구매 동의를 다시 받습니다. 충전 완료만으로 해당 상품을 자동 구매하지 않습니다.
- 구매 대기 중 계정이 바뀌면 현재 요청을 거절합니다. 구매가 이미 서버에 반영됐으나 응답이 끊긴 경우 같은 계정으로 다시 선택하면 소유권을 확인해 추가 차감 없이 사용할 수 있습니다.
- 직접 입력한 글, 글꼴, 기본 텍스트 꾸미기는 유료 문구 상품에 포함하지 않습니다. 기본 사진 프레임과 상품으로 등록하지 않은 기존 장식도 무료입니다.

공통 적용 판단은 [point_shop_access.dart](../lib/features/point_shop/presentation/point_shop_access.dart), 계정 전환 검사와 서버 호출은 [point_shop_repository.dart](../lib/features/point_shop/data/point_shop_repository.dart)에 있습니다.

## 관리자 가격 설정

1. 관리자 계정으로 로그인한 뒤 **마이페이지 → 포인트 상점 관리 → 상품 가격 관리**로 이동합니다. 화면 제목은 `포인트 상품 관리`입니다.
2. 템플릿·스티커·문구·프레임 필터와 검색으로 상품을 선택합니다. 목록에는 현재 앱이 공개한 자산이 표시되며, 각 자산에 저장된 서버 가격 설정을 합쳐 보여 줍니다. 현재 공개 목록에 없는 자산은 이 관리자 화면에서 신규 판매 대상으로 추가하지 않습니다.
3. 무료 공개는 `0`, 유료 판매는 양의 정수 포인트를 입력합니다. 가격을 비워 두면 미설정 상태로 저장할 수 있지만 판매 활성화는 할 수 없습니다.
4. `판매 활성화`를 켜고 저장합니다. 판매를 중지할 때는 이 스위치를 끄고 저장합니다. 기존 구매 이력을 삭제하거나 상품 키를 바꾸지 않습니다.
5. 사용자 계정에서 가격 표시와 새 적용 권한을 확인합니다. 이미 구매한 계정에서는 판매 중지 후에도 적용되는지 확인합니다.

관리자 UI는 서버가 발급한 `app_metadata.role == 'admin'`을 사용합니다. 실제 상품 쓰기 권한도 DB의 `public.is_admin()` 및 RLS로 검사합니다. 일반 사용자가 편집할 수 있는 `user_metadata`는 관리자 권한이 아닙니다. 관리자 계정 부여·변경은 이 화면의 기능에 포함되지 않습니다.

가격은 0부터 2,147,483,647까지의 정수입니다. 음수·소수·유효하지 않은 입력은 저장할 수 없습니다. 저장 실패 시 입력을 유지해 재시도할 수 있습니다. 후보·퇴역 컬렉션을 신규 판매 대상으로 자동 등록하지 않습니다.

구현: [관리자 화면](../lib/features/profile/presentation/views/admin_point_shop_management_screen.dart), [마이페이지 동선](../lib/features/profile/presentation/views/my_page_screen.dart), [공개 상품 목록](../lib/features/point_shop/domain/point_shop_known_products.dart).

## 상품 키 규칙

상품 키는 **소문자 종류 + `:` + 원래 자산 ID**입니다. 자산 ID의 대소문자를 보존하며 전체 문자열을 소문자로 바꾸지 않습니다. 같은 자산의 표시명·미리보기·화면 위치가 바뀌어도 키는 유지합니다.

| 자산 | 키 생성 기준 | 예시 |
| --- | --- | --- |
| 자체 제작 앨범 컬렉션 | `template:${AuthoredCollection.id}` | `template:lightbound` |
| 그 외 서버 템플릿 | `template:server-${PremiumTemplate.id}` | ID가 123인 경우 `template:server-123` |
| 스티커·종이·테이프 장식 | `sticker:${StudioDecorationSpec.id}` | `sticker:studioCottonRag` |
| 준비된 문구 | `phrase:${StudioPhrase.id}` | `phrase:vow-day` |
| 사진 프레임 | `frame:${ImageFrameStyle.key}` | `frame:studyArchWindow` |

자체 제작 컬렉션은 `bundledId`가 같은 `PremiumTemplate`도 컬렉션 키로 변환합니다. 스토어·생성 화면·편집기의 같은 컬렉션과 화면 비율별 변형을 서로 다른 상품으로 중복 판매하지 않습니다. 매핑은 [point_shop_template_key.dart](../lib/features/point_shop/domain/point_shop_template_key.dart)를 공통으로 사용합니다. 별도 `DesignTemplate` 자산을 적용하는 패널은 해당 자산의 안정적인 ID를 `template:<id>`로 사용합니다.

DB는 종류를 `template`, `sticker`, `phrase`, `frame`으로 제한하고 `product_key = kind || ':' || asset_id`를 검사합니다. 자산 ID는 1~180자이며 아래 형식을 따릅니다. 콜론과 공백은 자산 ID에 포함할 수 없습니다.

```text
^[A-Za-z0-9_-][A-Za-z0-9._/-]{0,179}$
```

## 포인트 충전과 실물 인쇄의 구분

포인트 충전 동선은 **마이페이지 → 포인트 충전**입니다. 앱이 판매하는 충전 상품은 Android Google Play Billing과 iOS Apple 인앱결제의 **소모성 포인트 SKU**뿐입니다. 구독·외부 결제사·디지털 자산별 별도 스토어 SKU를 추가하지 않습니다. 충전된 포인트로 위 디지털 상품을 구매합니다.

현재 앱 기본 SKU는 `snapfit_points_2500`, `snapfit_points_8000`, `snapfit_points_18000`입니다. 빌드 설정 `IAP_POINT_PRODUCT_IDS`, 실제 스토어 상품, 서버 `point_products`가 일치해야 합니다. 앱의 상품 ID 접미사나 클라이언트 요청만으로 포인트를 지급하지 않으며, 서버의 스토어 검증과 상품 설정을 기준으로 지급합니다.

현재 기록된 준비 상태는 Android·iOS 모두 **`UNAVAILABLE`**입니다. Google Play 검증 환경과 Apple 검증 키·상품 설정을 완성해야 하며, 실제 스토어 충전 검증은 남아 있습니다. 새 앱은 서버 준비 상태를 먼저 확인하고 준비되지 않은 경우 스토어 결제창을 열지 않습니다. `READY` 응답만으로 실구매·복구·환불 검증이 끝난 것은 아닙니다.

설정 및 충전 거래 복구: [포인트 구매 운영](POINT_PURCHASE_OPERATIONS.md), [Android 준비 점검표](ANDROID_POINT_PURCHASE_CHECKLIST.md), [최신 적용 현황](PAYMENT_PUSH_DEPLOYMENT_STATUS.md).

**실물 인쇄 주문에는 IAP 포인트를 사용하지 않습니다.** 현재 고객용 인쇄 주문은 `준비 중` 안내에서 새 결제·주문 진행을 막고 기존 주문 이력을 유지합니다. 인쇄 주문에 적용할 별도 결제 방식·가격 정책은 사용자 확인 대기 항목이며, 이 디지털 상점 구현에서 대체 결제사나 임의의 포인트 인쇄 가격을 만들지 않습니다.

## 서버의 차감·소유권 보장

권한 조회 RPC는 `get_point_shop_access(p_product_key)`, 구매 RPC는 `purchase_point_shop_product(p_product_key, p_expected_price)`입니다. 조회는 비회원에게도 허용하지만 유료 구매는 로그인한 사용자의 `auth.uid()`로만 처리합니다. 클라이언트가 구매 대상 계정이나 지급할 소유권을 지정할 수 없습니다.

구매는 하나의 DB 트랜잭션에서 다음과 같이 처리합니다.

1. 상품 행에 공유 잠금을 걸고 기존 소유권을 우선 확인합니다. 소유 중이면 판매 상태·가격 변경과 관계없이 추가 차감 없이 반환합니다.
2. 판매 상태와 서버 가격을 확인합니다. 사용자가 확인한 `p_expected_price`와 다르면 거절해 변경된 금액을 묵시적으로 차감하지 않습니다.
3. 사용자 지갑 행을 잠그고 소유권을 다시 확인합니다. 잔액이 부족하면 거절합니다. 충전 환불로 발생한 음수 잔액도 그대로 반영합니다.
4. 차감 원장·지갑 잔액·구매 소유권을 함께 기록합니다. 어느 단계든 실패하면 모두 롤백합니다.

소유권은 `(user_id, product_key)` 기본 키로 중복을 막습니다. 원장 이유는 `DIGITAL_ITEM_PURCHASE`, 거래 연결 대상은 `point_shop_product`, 멱등 키는 `digital_item:<사용자 UUID>:<상품 키>`입니다. 지갑 잠금은 같은 계정의 서로 다른 상품 구매도 직렬화해 같은 잔액을 중복 소비하지 않도록 합니다.

일반 클라이언트는 소유권을 직접 추가·수정·삭제할 수 없습니다. 구매 원장과 소유권의 사용자·금액·상품·멱등 키를 DB 트리거로 대조하고, 유료 구매 원장과 소유권의 임의 변경을 막습니다. 계정 삭제에 따른 정리는 허용합니다. 일반 운영에서 소유권 회수·이전·디지털 상품 환불을 수행하는 관리자 UI는 제공하지 않습니다.

구현은 [디지털 상점 마이그레이션](../supabase/migrations/20260908111001_digital_point_shop.sql)에 있습니다. 빈 마이그레이션 적용 이력에서 누락된 스키마를 보완하는 [후속 마이그레이션](../supabase/migrations/20260908112124_complete_digital_point_shop_schema.sql)은 필요한 테이블·RPC·보호 함수가 모두 없으면 설치하고, 모두 있으면 데이터를 유지한 채 종료합니다. 일부만 있는 경우 `partial_point_shop_schema_requires_review`로 중지합니다. 이미 적용한 마이그레이션 이력을 수정하지 않습니다.

PGlite 검증은 운영 PostgreSQL의 여러 연결에서 발생하는 동시 요청 시험이나 실제 스토어 결제를 대체하지 않습니다. 테스트 계정과 승인된 테스트 환경에서 다음을 확인합니다.

1. **무료·미설정:** 비회원으로 미등록 자산과 활성 0P 자산을 적용합니다. 가격 미설정·판매 중지 상품은 미리보기만 되고 새 적용은 차단되는지 확인합니다.
2. **상품 네 종류:** 템플릿·스티커·문구·프레임을 각각 선택해 가격·잔액을 확인합니다. 취소하면 앨범이 바뀌지 않고, 승인하면 원장 1건과 소유권 1건만 생기는지 확인합니다.
3. **재이용:** 같은 계정으로 앱 재실행·재로그인·다른 기기에서 다시 적용합니다. 다른 계정에는 소유권이 보이지 않아야 합니다. 같은 컬렉션의 비율별 템플릿도 추가 차감되지 않아야 합니다.
4. **변경·장애:** 구매 확인 중 가격 변경, 판매 중지, 계정 전환, 네트워크 단절을 재현합니다. 실패·취소 시 새 적용이 없어야 하며, 서버 반영 후 응답 유실은 재시도로 복구되고 중복 차감되지 않아야 합니다.
5. **동시성:** 동일 계정으로 별도 연결에서 같은 상품과 서로 다른 상품을 동시에 구매합니다. 같은 상품은 1회만 차감되고, 다른 상품의 합계가 잔액을 넘으면 초과 구매가 거절되어야 합니다.
6. **운영자:** 일반 계정의 직접 상품 쓰기가 거절되는지, 관리자가 0P·유료·미설정·판매 중지를 저장할 수 있는지 확인합니다. 판매 중지·가격 변경 후 기존 소유자는 계속 적용할 수 있어야 합니다.
7. **충전 복귀:** Android 라이선스 테스트와 iOS Sandbox에서 포인트 충전 후 원래 상품으로 돌아옵니다. 최신 가격과 잔액을 다시 확인한 뒤에만 디지털 상품 구매가 진행되어야 합니다. 충전 취소·대기·중복 전달·앱 종료 복구·환불도 충전 운영 점검표에 따라 확인합니다.
8. **실물 인쇄:** 인쇄 주문의 준비 중 안내와 기존 주문 이력을 확인합니다. 디지털 상품 구매나 포인트 충전이 인쇄 주문 결제로 연결되면 안 됩니다.
