# 포인트 이용내역 — 오래된 내역 누락 개선

최근 5건을 전체 내역처럼 사용해 과거 차감이 `내역 없음`으로 보이는 문제를 현재 화면에서 재현하고 수정했다. 조회·필터·더보기의 기능 개선이며 잔액과 충전 화면을 새로 꾸미지는 않았다.

## 실제 문제와 반영 결과

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 차감 필터 | 최근 적립 5건에만 필터 → 그 이전 차감 1건을 못 찾음 | 서버에서 차감부터 필터링 → 이전의 -700P 내역 확인 |
| 전체 내역 | 요약용 최신 5건에서 종료 | 20건씩 조회하고 `이전 내역 더 보기`로 연결 |
| 후속 조회 실패 | 이어 읽는 경로 없음 | 이미 읽은 행과 커서를 보존하고 같은 페이지 재시도 |
| 적립/차감 표시 | 대각선 화살표 | + / −, 0P는 영수증 아이콘 |

캡처의 11,800P와 6개 거래는 합성 데이터다. 실제 계정이나 잔액을 조회하거나 변경한 결과가 아니다.

## 단계별 확인

1. **전체 내역 — 기존 구성 유지, 조회 범위 개선.** 잔액·탭·행 배치를 유지했다. 상세 화면은 요약용 5건과 별도 조회하며, 상세 탭을 볼 때만 데이터를 요청한다. 기존 요약의 5건 계약은 그대로다.

![전체 내역과 적립 표시](sandbox:/Users/devsheep/SnapFit/SnapFit/docs/verification/points-history-2026-11-12/after/01-history-all-390x844.png)

2. **차감 필터 — 잘못된 빈 결과 수정.** 변경 전 실제 요청은 `limit=5`였고, 데이터에 존재하는 여섯 번째 차감이 화면에 없었다. 변경 후 필터를 서버 조회에 포함해 해당 행을 표시한다. 전체의 0P 기록도 보존하며 적립·차감에는 각각 양수·음수만 조회한다.

| 변경 전 | 변경 후 |
| --- | --- |
| [390×844 라이트: 잘못된 빈 결과](before/02-history-spent-390x844.png) | [320×844 다크·글씨1.6배: 이전 차감 확인](after/03-history-spent-320x844-dark-large-text.png) |

두 이미지는 같은 거래 데이터지만 화면 크기·테마가 다르다. 390 라이트 차감 이미지의 고정 상단 누락 현상으로 전체 화면 비교에서 제외하고, 내용이 모두 보이는 다크 이미지를 채택했다.

![이전 차감 내역 확인](sandbox:/Users/devsheep/SnapFit/SnapFit/docs/verification/points-history-2026-11-12/after/03-history-spent-320x844-dark-large-text.png)

3. **더보기 — 이전 행을 유지하면서 이어 조회.** 생성 시각과 ID 내림차순 커서를 사용한다. 같은 시각의 거래를 구분하며 페이지 이동에 offset을 쓰지 않는다. 추가 1건으로 다음 페이지 유무를 판정한다. 아래는 25건 fixture 중 처음 20건을 읽은 목록 끝이며 버튼은 아직 누르지 않은 캡처다. 버튼을 눌러 나머지 5건을 읽는 동작은 위젯 테스트로 확인했다.

![이전 내역 더 보기](sandbox:/Users/devsheep/SnapFit/SnapFit/docs/verification/points-history-2026-11-12/after/04-history-more-390x844.png)

4. **오류·새로고침·계정 전환 — 상태 보호.** 다음 페이지 실패 시 기존 행을 유지하고 재시도한다. 진행 중 더보기 중복 요청을 막고, 새로고침은 첫 페이지로 되돌린다. owner/filter 변경 및 A→B→A의 늦은 응답을 차단한다. 기존 충전·적립·구매 성공과 새로고침 11곳에서 상세 페이지 상태도 무효화한다. 결제·지갑 변경 로직을 바꾸지 않았다.

## 검증

관련 기능 **85건 통과, 실패·건너뛰기 0건**이다.

| 검증 | 통과 |
| --- | ---: |
| 페이지 저장소·실제 Supabase 요청 빌더 | 19 |
| 페이지 상태·경합·계정 전환 | 12 |
| 실제 화면의 필터·더보기·오류·작은 화면 | 6 |
| 기존 BillingRepository | 11 |
| 기존 소유자 보호 | 6 |
| 충전·이용내역 반응형 회귀 | 26 |
| AI 제작 화면 복귀 | 5 |
| 합계 | 85 |

첫 실패 회귀를 기존 화면에서 확인한 뒤 구현했다. 설치된 SDK의 실제 요청 빌더와 메모리 HTTP 전송으로 본인 조건·서버 필터·정렬·동일 시각 커서·limit/lookahead를 검증했다. 실제 운영 DB 쿼리 실행과 구분한다.

변경 18개 파일 정적 분석은 `No issues found!`다. 독립 코드 검토도 완료했으며 남은 지적은 없다. 기존 위젯 fixture는 새 상세 계약에 맞췄고, 설치된 Riverpod family override 및 HTTP 응답의 request 연결도 검증 환경에 맞췄다. 네이티브 캡처 4개 시나리오가 통과했으며 채택한 최종 PNG는 직접 열어 확인했다.

## 범위와 한계

- 현재 Flutter 위젯·실제 번들 폰트와 메모리 인증/원장/구매 대역을 사용했다. 캡처의 구매 호출은 0회다. 실제 충전·결제·잔액 변경·운영 DB/스키마 변경은 하지 않았다.
- 390×844 라이트, 320×844 다크·글씨1.6배를 캡처했다. 320×568·회전·다른 크기의 레이아웃은 관련 위젯 테스트로 검사했으며 모든 크기를 이미지로 확인했다는 뜻은 아니다.
- 일부 네이티브 오프스크린 캡처에서 고정 상단/잔액 텍스트가 누락된 파일은 제외했다. 제외 목록과 정확한 요청 지표는 verification.json에 기록했다.
- 모바일·웹 코드는 같은 상세 상태를 사용한다. 이번 웹은 연결과 정적 분석 범위이며 실제 브라우저 화면 검증은 아니다. 전체 앱 빌드·실기기·스크린리더·색 대비 수치 검증도 하지 않았다.
- 커서는 새 거래로 offset 위치가 밀리는 문제를 피한다. DB 전체의 시점 고정 스냅샷이나 서버 거래 수정/삭제까지 격리하는 기능은 아니다.
- 검증용 임시 컴파일 파일은 종료 후 제거했다.

참고한 공식 API: [Supabase Dart or](https://supabase.com/docs/reference/dart/or), [order](https://supabase.com/docs/reference/dart/order). SDK 버전은 기존 잠금 파일을 유지했다.
