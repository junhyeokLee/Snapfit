# 다음 개선 우선순위

2026-11-12 · 현재 구현의 실제 위젯으로 재현한 후속 점검

**추천 순서는 ① 로그인·계정 복구 ② 사진 선택 오류 안내 ③ 프로필 수정 이탈 보호다.**

초기에는 사진 선택을 먼저 검토했지만, 추가 캡처에서 인증 화면의 배경·글자색 문제가 확인되어 인증을 1순위로 올렸다. 이번에는 문제 재현과 범위 제안만 했으며 제품 코드는 변경하지 않았다.

| 순위 | 개편·개선 범위 | 확인한 불편 | 우선순위 근거 |
| --- | --- | --- | --- |
| 1 | 로그인·계정 복구 | 라이트 테마의 이메일·재설정 화면에 검정 배경과 어두운 글자가 함께 나타남. 비밀번호 변경 성공 후에도 주 버튼이 ‘다시 변경하기’. 발송 후 주소를 바꾸어도 이전 발송 안내가 남음 | 서비스 진입과 계정 복구의 기본 가독성·다음 행동에 영향 |
| 2 | 사진 선택 실패 안내 | 사진 라이브러리 조회 예외가 실제 빈 라이브러리와 같은 ‘이미지 앨범이 비어 있어요’ 화면으로 표시됨 | 기록과 앨범 편집의 공통 사진 진입점에서 원인을 오해하게 함 |
| 3 | 공개 프로필 수정 이탈 | 소개를 바꾼 뒤 저장하지 않고 뒤로가면 확인 없이 닫히며, 재진입 시 작성한 내용이 사라짐 | 작성 손실을 작은 범위의 수정으로 방지 가능 |

## 1. 로그인·계정 복구

**확인한 사실**

- 동영상 초기화 성공 상태에서도 이메일 로그인으로 전환하면 `VideoPlayer`가 제거되고 라이트 테마가 적용되지만 Scaffold 배경은 검정이다. 재설정 요청 화면도 같은 상태다.
- 초기화 실패 경로에서도 검정 배경이 남는다. 캡처 바탕을 보정하거나 가리지 않았다.
- 비밀번호 변경 성공 응답 후 완료 안내가 표시되지만, 주 행동은 계속 ‘다시 변경하기’다. ‘이메일 로그인으로 돌아가기’는 같은 화면 내부 모드만 바꾼다.
- `first@example.test`로 발송을 요청한 뒤 입력을 `changed@example.test`로 바꾸어도 ‘입력한 이메일로 재설정 링크를 보냈어요’가 남는다. 두 번째 주소로 요청한 것은 아니다.

**개선 범위**

- 영상이 보이는 상태와 일반 입력 화면의 배경·글자색 판단 기준을 맞춘다. 밝은 테마·어두운 테마·영상 로딩/실패를 각각 확인한다.
- 변경 완료 후에는 완료와 복귀가 주 행동이 되게 한다. 실제 인증 상태에 따른 로그인 또는 앱 복귀 목적지를 명확히 한다.
- 발송 안내는 요청한 주소와 연결한다. 주소 변경 시 이전 성공 안내를 초기화하거나, 발송 요청한 주소를 명확히 표시한다.

**근거 캡처**

- [정상 초기화 후 이메일 로그인](screens/10-initialized-video-email-form.png)
- [정상 초기화 후 비밀번호 찾기](screens/11-initialized-video-reset-form.png)
- [변경 전](screens/03-password-before-submit.png) → [변경 완료](screens/04-password-complete.png) → [로그인 복귀 버튼 선택 후](screens/05-password-return-shows-login.png)
- [첫 주소로 요청](screens/06-reset-email-sent.png) → [주소를 수정한 상태](screens/07-reset-email-edited.png)

**코드 근거:** `login_screen.dart:94`, `:112`, `:119`, `:638`, `:1119`, `:1219`, `:1230`.

**검증 한계:** 동영상 플랫폼은 초기화 상태를 제공하는 대역이며 실제 영상 프레임·재생 품질은 점검하지 않았다. 폼에 영상 위젯이 없음을 별도로 확인했으므로 검정 배경은 영상 캡처 누락이 아니다. 실제 메일 발송·비밀번호 변경·복구 링크·AuthGate 전체 복귀는 실행하지 않았다. `main.dart:716`의 복구 화면 push 구조는 코드 확인이며, 실제 세션에서 홈 복귀 실패를 재현했다고 보지는 않는다.

## 2. 사진 선택 실패 안내

**확인한 사실**

사진 권한을 허용한 상태에서 실제 `showPhotosSelectionSheet`를 열었다. 한 시나리오에서는 저장소 조회가 예외를 던지고, 다른 시나리오에서는 정상적으로 빈 목록을 반환했다. 두 경우 모두 ‘이미지 앨범이 비어 있어요’와 사진 접근 범위를 넓히라는 같은 안내가 나타났다.

**개선 범위**

- 조회 실패에는 ‘사진을 불러오지 못했어요’와 재시도를 안내한다.
- 실제 빈 목록에는 사진이 없는 상태를 안내한다.
- 권한 오류에 이미 존재하는 설정·재시도 분기는 유지한다. 재시도 버튼 자체는 현재도 있으므로 새로 없는 기능처럼 추가하지 않는다.
- 안내와 버튼은 원인에 맞는 것만 표시하고 사진 선택 시트 전체 구조는 유지한다.

**근거 캡처:** [조회 실패](screens/01-gallery-query-failed.png), [실제로 빈 목록](screens/02-gallery-truly-empty.png).

**코드 근거:** `gallery_notifier.dart:58`, `:85`, `album_bottom_sheet.dart:27`, `:34`. 조회 예외는 보관되지만 화면은 권한 관련 문자열인지 여부로만 제목을 나눈다.

**검증 한계:** 기기 사진을 읽지 않고 저장소 대역으로 오류와 빈 목록을 제공했다. 운영체제의 일부 사진 허용·설정 이동·실제 대용량 라이브러리는 별도 확인 대상이다.

## 3. 공개 프로필 수정 이탈 보호

**확인한 사실**

실제 `SocialProfileEditScreen`에서 소개를 수정하고 `Navigator.maybePop()`으로 돌아갔다. 확인창 없이 화면이 닫혔으며, 다시 열면 원래 소개로 돌아왔다.

**개선 범위**

- 닉네임·아이디·소개가 저장된 값과 달라졌을 때만 ‘계속 수정 / 나가기’를 확인한다.
- 상단 뒤로가기와 시스템 뒤로가기에 같은 기준을 적용한다.
- 값을 원래대로 돌리거나 저장을 완료했다면 바로 닫을 수 있게 한다.
- 계정 전환 시 정보 초기화와 이미 별도로 확인하는 프로필 사진 변경은 유지한다.

**근거 캡처:** [저장하지 않은 소개](screens/08-profile-unsaved-draft.png) → [재진입 후 원래 소개](screens/09-profile-reentered.png).

**코드 근거:** `social_profile_edit_screen.dart:318`, `:331`. 현재 PopScope는 저장·사진 처리 중 여부만 확인한다.

**검증 한계:** 소개 수정의 이탈을 재현했다. 실제 프로필 저장이나 사진 업로드는 하지 않았다. 상단·운영체제별 뒤로가기의 최종 동작은 구현 단계에서 각각 확인해야 한다.

## 확인한 단계와 상태

| 단계 | 관찰 상태 | 판정 |
| --- | --- | --- |
| 영상 초기화 → 이메일 로그인 → 비밀번호 찾기 | 초기화는 성공, 폼에는 영상 없음, 검정 배경과 라이트 테마 혼재 | 우선 개선 |
| 비밀번호 입력 → 변경 성공 → 복귀 선택 | 성공 안내는 있음. 반복 변경이 주 행동이고 복귀는 내부 모드 전환 | 다음 행동 개선 |
| 재설정 메일 요청 → 주소 수정 | 이전 발송 안내 유지 | 상태 안내 개선 |
| 사진 선택 → 조회 실패 | 정상 빈 목록과 같은 안내 | 오류 안내 개선 |
| 사진 선택 → 정상 빈 목록 | 빈 목록 안내와 다시 불러오기 표시 | 오류 상태와 구분 필요 |
| 프로필 수정 → 뒤로가기 → 재진입 | 확인 없음, 임시 작성 내용 사라짐 | 이탈 보호 필요 |

현재 확보한 근거로 피드·검색·사진 정렬·선택 목록을 전면 개편할 필요는 제시하지 않는다. 이미 완료한 홈·기록·리더 넘김·고객센터·편집 안내는 이번 순위에서 제외했다. 전체 앱의 모든 화면을 실제 기기에서 검증했다는 의미는 아니다.
