# SnapFit 전체 UX 재점검 — 실제 개선 우선순위

> 승인된 3곳의 구현과 전후 검증: [반영 결과](../priority-ux-improvements-2026-11-11/README.md). 아래는 구현 전 점검 기록입니다.

2026-11-11 현재 작업 소스를 기준으로 주요 사용자 흐름을 다시 대조했다. 코드상 의심 지점을 실제 Flutter 위젯으로 재현하고 저장된 PNG 8장을 모두 열어 확인했다. 이번 작업의 결과는 개선 대상 선정이며 제품 코드는 변경하지 않았다.

이전 리더 작업은 현재 페이지 연결·복귀 오류 수정이었다. 정적인 화면 차이가 거의 없었으므로 이를 큰 디자인 변화로 설명하지 않는다. 이번에는 사용자의 목표를 방해하는 화면 구조와 불필요한 단계만 우선 대상으로 골랐다.

## 결론

| 우선순위 | 실제 문제 | 바꿀 방향 | 보존할 것 |
| --- | --- | --- | --- |
| 1 | 한 달 완주가 핵심인데 홈은 이번 주 7일만 보여줌 | 주간 줄을 작은 월 전체 기록판으로 교체. 채운 날·놓친 날·오늘을 표시 | 오늘 기록, 당일 사진 조건, 한 달 전 일수 완주 1,000P, 모아둔 순간, 큰 내 앨범 |
| 2 | 주문 불가 상태에서도 배송지를 다 입력한 뒤 막힘 | 주문 가능 여부를 미리보기의 금액 근처에서 먼저 안내하고 불필요한 주소 입력을 차단 | 인쇄 배치 확인, 계속 편집, 최종 동의, 관리자 TEST 권한 |
| 3 | 20쪽 공개 최종 확인에서 버튼까지 약 11.5화면 길이 | 대표 페이지 + 작은 선택 목록 + 선택한 쪽 확대 확인으로 압축 | 공개할 쪽 선택, 순서 조정, 공개 범위 안내, 명시적 동의 |

색상·모서리·여백을 바꾸는 작업, 좋은 화면을 새로 꾸미는 작업은 우선 대상에서 제외했다. 이는 모든 영역에 문제가 없다는 보증이 아니다.

## 전체 흐름 대조 범위

| 영역 | 이번 판단과 근거 |
| --- | --- |
| 소개·로그인·인증 복구 | 현재 코드에서 주요 진입·복구 경로 확인. 소개가 디자인 제작 중심인 점은 남은 가설이나 이번 현재 화면으로 재현하지 않았으므로 확정 개선으로 올리지 않음 |
| 홈·월간 보상 | 현재 코드 + 이번 실제 중순 2상태 캡처. 우선 개선 1 |
| 오늘 사진·글 작성 | 현재 코드의 사진 선택·비공개/공개·임시 작성·날짜 제한 경로 확인. 이미 사진 중심 구성이므로 과거 설명 밀도 지적을 그대로 재사용하지 않음 |
| 모아둔 순간·월간 앨범 연결 | 현재 홈 구간 실행에서 사진 원래 비율과 앨범 연결 확인. 유지 |
| 디자인 선택·무료/유료·설정 | 현재 제작 흐름 대조. 이미 선택한 개선 방향 유지. 필수 사진 채우기 단계 재추가하지 않음 |
| 표지·내지 편집 | 기존 편집기와 통합 진입 방향 유지. 다시 교체할 근거 없음. 이번 전 도구·기기 동작 전체를 재검증한 것은 아님 |
| 저장·감상 | 직전 오류 수정 범위와 구분. 큰 앨범·썸네일·사진 비율을 다시 바꾸지 않음 |
| 스토어·디자인 상세·보관함 | 현재 소스에는 검색·카테고리·무료/유료·조건 해제·빈 결과 재탐색이 존재. 과거 스토어 캡처의 소개 패널은 현재 제거되어 있어 증거에서 제외. 추가 재배치 보류 |
| 피드·검색·개인/공개 프로필 | 현재 코드에 역할 분리와 탐색이 존재. 취향 차원의 리디자인 필요성은 확인하지 못함 |
| 앨범 공개 | 현재 실제 20쪽 앨범의 최종 확인 실행·거리 측정. 우선 개선 3 |
| 초대·멤버·권한 | 현재 코드의 권한 안내·동작 제한 확인. 새 시안을 만들 근거 없음 |
| 포인트·설정·알림 | 현재 연결과 설정 상태 처리 대조. 월간 기록의 보상 조건을 출석·초대와 섞지 않음. 실제 알림 수신은 이번 범위 아님 |
| 인쇄·배송지·주문 확인 | 현재 canPay=false 상태로 실제 4단계 재현. 우선 개선 2 |
| 주문 내역·문의 | 주문별 문의·배송 조회는 존재. 일반 문의의 답변 확인 경로는 운영 채널 확인이 필요해 이번 디자인 변경으로 확정하지 않음 |

전체 실행 검증 또는 모든 화면의 실기기 검증을 완료했다는 뜻은 아니다. 현재 화면으로 확인한 3구간과 소스 대조 영역을 구분했다.

## 재현 조건과 한계

- 논리 화면 390×844, DPR 2, 실제 번들 폰트. 공개와 주문 미리보기는 현재 카탈로그 템플릿 -9501의 실제 사진·레이어를 사용했다.
- 홈은 실제 홈의 기록 요약 → 모아둔 순간 → 월간 앨범 연결 위젯 순서를 사용했다. 앱 내비게이션·개인 앨범 선반을 포함한 HomeScreen 전체 캡처는 아니다. 11월 18일은 중순 상황을 보기 위한 합성 날짜다.
- canPay=false와 예시 가격은 재현용 메모리 저장소 값이다. 운영 주문 서비스가 현재 막혀 있다는 주장이나 운영 가격 확인이 아니다.
- 공개는 누르지 않았다. 업로드·주문 생성·결제·문의 발송·운영 DB 변경은 실행하지 않았다.
- 4개 캡처 시나리오가 통과했다(home 2, print 1, publish 1). 이 숫자는 제품 기능 전체의 테스트 통과 숫자가 아니다.
- 키보드·스크린리더·색 대비 수치·큰 글자·실기기 권한·브라우저·모든 오류 상태는 이번 캡처만으로 검증되지 않는다. 공개의 긴 스크롤은 탐색·운동 부담의 근거지만 접근성 전체 부적합 판정은 아니다.

## 단계별 현재 화면과 판단

### 1. 홈: 완주 가능한 중순

![홈: 완주 가능한 중순](sandbox:/Users/devsheep/SnapFit/SnapFit/docs/verification/whole-ux-audit-2026-11-11/home/01-home-on-track-390x844.png)

진행 일수와 오늘 기록 버튼은 명확하다. 다만 17/30 아래에는 16~22일만 보여 지난 주에 쌓은 기록과 남은 달을 볼 수 없다.

유지: 보상 조건·오늘 기록·모아둔 순간·앨범 연결. 개선: 주간 줄을 월 전체 기록판으로 교체한다.

### 2. 홈: 지난 날짜를 하루 놓친 중순

![홈: 지난 날짜를 하루 놓친 중순](sandbox:/Users/devsheep/SnapFit/SnapFit/docs/verification/whole-ux-audit-2026-11-11/home/02-home-missed-day-390x844.png)

8일을 놓친 상태를 재현했다. 이번 달 보상 불가라는 문장은 있지만 어느 날을 놓쳤는지 화면에서 알 수 없다. 이 상태에서는 누적 일수 표시도 보상 불가 문장으로 대체된다.

개선: 채운 날·놓친 날·오늘·미래를 구분하고 쌓은 기록의 진행은 계속 보여준다. 지난 날짜 추가 금지와 1,000P 조건은 유지한다.

### 3. 인쇄 미리보기: 가격과 책 확인

![인쇄 미리보기: 가격과 책 확인](sandbox:/Users/devsheep/SnapFit/SnapFit/docs/verification/whole-ux-audit-2026-11-11/print/print-01-preview-top.png)

표지·규격·금액은 읽기 쉽다. 서버가 canPay=false / PREPARING을 반환한 fixture인데 최종 판매가 안내는 배송지 입력을 유도한다.

개선: 가격 승인 여부와 실제 주문 가능 여부를 구분해 이 단계에서 함께 안내한다. 예시 금액 49,900원은 테스트 데이터이며 운영 가격 확인 결과가 아니다.

### 4. 인쇄 미리보기: 배송지 입력 버튼

![인쇄 미리보기: 배송지 입력 버튼](sandbox:/Users/devsheep/SnapFit/SnapFit/docs/verification/whole-ux-audit-2026-11-11/print/print-02-delivery-enabled-when-blocked.png)

배치 확인 체크 후 버튼이 활성화된다. 이미 받은 서버 주문 불가 상태와 관계없이 배송지 화면으로 이동한다.

개선: 일반 주문이 불가한 경우 배송지 입력 전에 준비 상태와 다음 행동을 보여준다. 관리자 개발 TEST의 별도 권한 경로는 보존해야 한다.

### 5. 배송지 입력

![배송지 입력](sandbox:/Users/devsheep/SnapFit/SnapFit/docs/verification/whole-ux-audit-2026-11-11/print/print-03-address-before-readiness.png)

입력 항목과 주소 검색은 찾기 쉽다. 이 화면에서도 일반 주문 불가 상태를 먼저 알려주지 않는다.

개선: 앞 단계에서 불필요한 입력을 막는다. 배송지 폼 자체를 새로 꾸밀 근거는 없다. 테스트 이름·전화·주소만 사용했다.

### 6. 배송지 작성 후 주문 내용 확인

![배송지 작성 후 주문 내용 확인](sandbox:/Users/devsheep/SnapFit/SnapFit/docs/verification/whole-ux-audit-2026-11-11/print/print-04-blocked-after-address.png)

이름·전화·주소를 모두 입력한 뒤 결제 준비 중인 버튼에 도달했다. 앞에서 주문 불가를 알 수 있었으므로 사용자의 입력이 낭비된다.

개선: 주문 가능 여부를 미리보기로 앞당긴다. 동의·최종 금액 확인과 서버의 결제 검증은 그대로 유지한다.

### 7. 20쪽 앨범 공개: 최종 확인 상단

![20쪽 앨범 공개: 최종 확인 상단](sandbox:/Users/devsheep/SnapFit/SnapFit/docs/verification/whole-ux-audit-2026-11-11/publish/social-publish-review-top.png)

선택한 공개 범위와 대표 페이지가 명확하다. 그러나 20개 페이지를 각각 큰 미리보기와 순서 버튼으로 모두 세로 나열한다.

개선: 대표 페이지 한 장과 선택 페이지 목록을 압축해 보여주고, 선택한 페이지를 크게 확인하게 한다. 공개 범위와 동의는 유지한다.

### 8. 20쪽 앨범 공개: 마지막 행동

![20쪽 앨범 공개: 마지막 행동](sandbox:/Users/devsheep/SnapFit/SnapFit/docs/verification/whole-ux-audit-2026-11-11/publish/social-publish-review-action.png)

공개 버튼은 마지막 페이지 아래에 있다. 상단에서 버튼까지 실제 스크롤 8,694 logical px / viewport 756px, 약 11.5화면 길이였다. 공개는 실행하지 않았다.

개선: 최종 공개 동작을 명확한 위치에 두고 긴 전체 페이지 검토와 분리한다. 페이지 순서 수정과 공개 동의 확인은 보존한다.

## 후속 적용 기준

먼저 홈의 월간 기록판과 주문 가능 여부 안내를 구체화한다. 공개 확인은 기존 큰 이미지 20장 나열을 압축하는 범위로 제한한다. 세 구간 모두 한 화면에서 무엇을 이해하고 다음에 무엇을 할 수 있는지가 분명해지는지 전후를 비교한다.

기존 편집기와 정상적인 스토어를 다른 시안으로 교체하지 않는다. 제품에 새로운 기능이나 운영상 존재하지 않는 답변 채널을 지어내지 않는다.

원본 PNG·스크롤 측정값·캡처 로그·소스 해시는 이 문서와 같은 폴더의 하위 폴더 및 `verification.json`에 보관했다.
