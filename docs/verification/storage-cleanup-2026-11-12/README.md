# SnapFit 저장 공간 정리 — 2026-11-12

사용자 요청에 따라 개선 작업 전에 정리했다. **재생성 가능한 파일 약 9.03GB**를 제거했고, 정리 직후 여유 공간은 **12.55GB**였다. GB는 10억 바이트 기준이다. 시스템의 다른 작업에 따라 현재 여유 공간은 달라질 수 있다.

| 정리 대상 | 제거한 용량 |
| --- | ---: |
| `/tmp/snapfit-*.dill` 검증용 임시 커널 37개 | 4.57GB |
| Flutter/Android build 결과와 일반 컴파일 캐시 | 4.45GB |
| 합계 | 9.03GB |

프로젝트에서 제거한 경로는 `build/`, `.dart_tool/flutter_build/`, `android/.gradle/`, `android/.kotlin/`다. 삭제 전에 Git 추적 파일이 없는지 확인했다. `android/build/`에는 추적 파일 2개가 있어 삭제 대상에서 제외했다.

원본 `assets/`, 작업 중인 소스, 템플릿 제작 원본, `output/`의 혼합 결과물, 최종 검증 이미지/보고서, `.git`, `pubspec.lock`, 인증/서명 파일은 보존했다. `output/`은 325개, `tmp/`는 3개 추적 파일이 있어 폴더 이름만으로 정리하지 않았다.

`.dart_tool/package_config.json`과 기존 웹 배포 호환성에 쓰이는 `web_entrypoint_history/`, `web_font_history/`도 유지했다. 네이티브 위젯 검사에 필요한 작은 폰트/자산 메타데이터는 build 폴더의 심볼릭링크에서 임시 폴더의 독립 파일로 먼저 분리했고, 실제 원본 assets 링크는 그대로 유지했다.

빌드·컴파일 캐시는 다음 개발 실행이나 빌드 때 다시 생성되므로 첫 실행 시간이 늘어날 수 있다. 앱 전체 빌드를 새로 실행하지는 않았다. [삭제 목록과 용량 기록](verification.json)

개선 검증 중 새로 생긴 임시 커널 5개(0.64GB)도 종료 후 다시 정리했다. 이는 위의 기존 파일 9.03GB와 별개로 이번 검증에서 생성된 파일이다. 최종 확인 시 여유 공간은 **11.50GB**였다.
