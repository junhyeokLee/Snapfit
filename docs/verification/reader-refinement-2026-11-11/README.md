# 앨범 감상·편집 복귀 개선 — 2026-11-11

현재 쪽을 편집하고 감상으로 돌아오는 흐름을 정리했다. 책 모양·사진 비율·기존 편집기는 유지했다.

## 반영한 동작

- 더보기의 모호한 `수정하기`를 `표지 편집` 또는 `N쪽 편집`으로 표시하고 실제 해당 쪽을 연다.
- 편집 중 앞쪽 페이지를 삭제하거나 순서를 바꿔도 같은 페이지 ID를 찾아 복귀한다. 해당 페이지가 삭제됐으면 가까운 유효 위치로 복귀한다.
- 상세 보기에서 마지막으로 넘긴 쪽을 감상 화면 복귀 시 반영한다. 상세 화면 뒤에서 책을 미리 움직이지 않는다.
- 오른쪽 페이지 포커스는 회전·렌더러 재생성·요청된 이동 완료 때도 유지한다.
- 편집 중 문서·세션·사용자가 바뀌면 이전 복귀 결과를 무시한다. 보기 전용 권한은 유지한다.
- 무변경 편집 복귀 뒤 다음 넘김을 막던 대기 상태와 이전 이동 작업의 늦은 완료를 방지한다.

최초 RED에서 메뉴 편집의 initialPageIndex 누락과 앞장 삭제 후 위치 불일치를 확인했다. 나머지 두 테스트의 중복 tooltip finder는 상세 화면으로 범위를 좁혀 정정했다. 이후 메뉴 무변경 복귀 후 실제 다음 버튼, 메뉴 편집 후 앞장 삭제·오른쪽 위치·회전 후 재편집을 포함해 최종 4개 모두 통과했다.

테스트는 설치된 Flutter frontend compiler와 flutter_tester를 사용해 동일 위젯 테스트 본문을 직렬 실행했다. 편집 route의 진입 인덱스 검증은 무거운 전체 편집기를 띄우지 않는 route observer를 사용한다. 화면 캡처는 실제 AlbumReaderScreen과 실제 템플릿 -9501의 폰트·사진을 사용했다. 합성 소유자·메모리 저장소의 앨범이며 운영 앨범이나 DB를 변경하지 않았다. 메모리 fixture에는 표지와 내지 4쪽의 콘텐츠를 넣었고 기존 VM의 최소 내지 규칙으로 총 20쪽이 표시된다.

수정 전 내지·메뉴·가로 3장, 수정 후 동일 3장과 상세 1장을 저장했다. 수정 전 표지 캡처는 정착 조건에 도달하지 않아 비교 자료에서 제외했다. 최종 검증은 내지·메뉴·가로·상세 범위이며 표지 단독 캡처, 웹 브라우저 실행, 전체 앱 빌드 및 기기 설치 검증은 포함하지 않는다. 웹 경로는 같은 callback 연결을 코드 검토하고 정적 분석했다.
