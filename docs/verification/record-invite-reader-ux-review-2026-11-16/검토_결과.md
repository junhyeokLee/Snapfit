1. 사진 삭제 — 의도하지 않은 두 번째 사진 제거

현재 삭제 버튼은 날짜 확인을 비동기로 기다리는 동안 활성 상태를 유지한다. 응답 뒤에는 캡처한 목록 인덱스로 `removeAt(i)`를 실행한다. 첫 번째 사진의 같은 버튼 요소를 두 번 누르고 두 날짜 응답을 완료하자 첫째·둘째 사진이 제거됐고 셋째만 남았다. 남은 사진의 객체와 기록 글은 유지됐으며 임시 작성의 사진도 1장으로 저장됐다.

재현에서는 원격 저장·공개 요청이 없었고 원래 기록의 사진 3장도 그대로였다. 확인 범위는 편집 목록과 임시 작성이며, 서버 기록이나 원본 파일의 영구 삭제를 확인한 것은 아니다.

2. 사용된 초대 — 로그인으로 확인할 기회가 없음

로컬 서버 소스는 이미 수락한 링크를 조회할 때, 현재 로그인 계정이 원래 수락자이고 현재도 참여 중인 경우 정보를 반환하도록 되어 있다. 비로그인 상태에는 `invite_used / 409`를 반환한다. 앱은 이 응답을 종료 상태로 처리해 `초대 닫기`만 보여 준다. 따라서 현재 문구는 본인이 사용한 링크에도 다른 사람이 사용했다고 안내할 수 있다.

10번 화면은 비로그인 409 응답 대역, 11번 화면은 원래 수락자가 로그인한 상태의 정상 응답 대역이다. 두 화면은 별도 재현이며 앱의 로그인 버튼으로 연결한 전후 화면이 아니다. 운영 서버 배포 상태나 실제 계정 로그인을 검증한 결과도 아니다.

개선 시 초대 토큰을 로그인 과정에 보존하고 로그인 후 서버에 재조회한다. 클라이언트 판단으로 앨범이나 권한을 열어 주지 않는다.

3. 초대 수락 지연 — 사용자가 빠져나갈 수 없는 대기 상태

응답을 완료하지 않는 저장소 대역으로 수락 요청을 1회 실행하고 가상 시간 31초를 진행했다. 버튼은 비활성 상태였고 닫기 버튼은 사라졌으며, 상단 뒤로가기와 Navigator의 일반 뒤로가기 요청 후에도 같은 초대 화면이 남았다. 실제 서버의 응답 시간을 측정하거나 영구적인 무한 대기를 증명한 것은 아니다.
