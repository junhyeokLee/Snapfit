## 1. 배송지 입력 오류 위치 안내

이름만 비우고 전화번호·우편번호·주소를 유효한 합성 값으로 입력했다. 하단 ‘주문 내용 확인하기’를 누른 뒤 오류가 실제 화면에 보이는지 확인했다. 화면 밖 오류가 생성되는 경우에는 사용자가 위쪽으로 돌아가 누락 항목을 찾아야 한다.

| 화면 조건 | 버튼 선택 후 이름 오류 위치 | 확인 결과 |
| --- | --- | --- |
| 390×844 · 글자 1배 | y124~141, 화면 내부 | 이번 조건에서는 문제 없음 |
| 320×568 · 글자 1배 | y−192~−175, 화면 밖 | 개선 필요 |
| 390×844 · 글자 1.6배 | y−116~−89, 화면 밖 | 개선 필요 |

세 조건 모두 버튼 선택 후 스크롤 위치는 바뀌지 않았고 이름 입력칸으로 포커스도 이동하지 않았다. 실제 결제 호출은 0회다.

작은 화면에서 버튼을 누른 뒤 보이는 화면과, 오류가 있는 위쪽 위치를 비교한다. 두 이미지는 이번 점검에서 캡처한 현재 앱 화면이며 개선 시안이 아니다.

## 2. 초대 화면 복귀 후 명단 갱신

처음 소유자와 편집자 2명이 보이는 실제 멤버 화면을 열었다. 짧은 목록에서도 당겨 새로고침은 정상 동작했다. 이후 실제 초대 화면으로 이동한 동안 대역 저장소에 세 번째 참여자를 추가했다. 복귀한 화면은 재조회 없이 2명을 계속 표시했고, 다시 당겼을 때 세 번째 참여자가 나타났다.

| 단계 | 저장소의 명단 | 명단 조회 횟수 | 현재 화면 |
| --- | ---: | ---: | --- |
| 멤버 화면 최초 진입 | 2명 | 1 | 2명 표시 |
| 짧은 목록에서 당김 | 2명 | 2 | 정상 새로고침 |
| 초대 화면 동안 새 참여 추가 → 복귀 | 3명 | 2 | 이전 2명 표시 |
| 복귀 후 수동 당김 | 3명 | 3 | 새 참여자 포함 3명 표시 |

## 제외한 후보와 검증 범위

처음 의심한 ‘짧은 멤버 목록은 당겨도 갱신되지 않는다’는 실제 실행에서 재현되지 않아 제외했다. 일반 크기 390×844의 배송지 오류도 보였으므로 모든 화면에서 발생하는 문제로 확대하지 않았다.

최종 재현 시나리오 5개가 통과했고 화면 18장을 확인했다. 통과는 현재 동작의 재현 성공을 뜻하며 수정 완료를 뜻하지 않는다. 점검용 코드 3파일 정적 분석은 이상 없음이다. 최초 가설이 틀렸던 실행 로그도 보관했다.

Android 테마의 실제 위젯과 앱 폰트를 사용했다. 초대 생성·멤버 참여·주문 가능 상태는 메모리 대역이며 실제 초대·메시지·결제·운영 DB 요청은 하지 않았다. 물리 기기·운영체제 키보드·스크린리더·전체 접근성 적합성은 확인하지 않았다. 배송지 오류 위치는 키보드를 닫은 상태에서 측정했다.
