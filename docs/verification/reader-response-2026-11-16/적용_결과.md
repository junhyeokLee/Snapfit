# 읽기 화면 첫 입력과 넘김 반응 개선

읽기 화면에 들어오자마자 발생한 스와이프·버튼 입력을 유지하고, 필요한 페이지부터 준비해 기존 책 넘김을 시작하도록 수정했습니다.

## 적용

- **현재·다음 넘김면 우선 준비:** 전체 앨범의 사진과 페이지 캡처가 끝날 때까지 첫 넘김을 막던 대기를 제거했습니다. 준비되지 않은 먼 페이지를 넘김에 사용하는 일은 방지합니다.
- **첫 입력 보존:** 준비 중 시작한 드래그는 같은 손가락 위치와 누적 이동량으로 이어집니다. 손을 먼저 떼도 넘김 의도를 유지하고, 짧은 취소 동작은 정상 복귀합니다. 버튼은 순간 이동하지 않고 기존 넘김을 시작합니다.
- **동작 중 배경 작업 양보:** 페이지 넘김·같은 펼침면의 카메라 이동 중에는 뒤쪽 페이지의 준비·캡처를 쉬고, 끝나면 재개합니다. 책 애니메이션 자체는 계속 동작합니다. 이미 진행 중인 캡처 한 건은 완료될 수 있습니다.
- **준비 완료 직후 경합 해소:** 텍스처가 준비됐지만 캔버스 배치가 아직 끝나지 않은 한 프레임에서는 입력을 잃지 않고 다음 배치 직후 다시 연결합니다.

표지↔내지 책 넘김, 500ms 완료 애니메이션, 페이지 번호·위치, 사진 품질 정책은 유지했습니다. 초기 커버 크기가 같을 때의 중복 화면 갱신도 줄였습니다.

## 검증

실제 Flutter 테스트 엔진에서 한 번에 한 프로세스씩 실행했습니다. **총 113개 통과, 실패·건너뜀 0개**, 수정 8개 파일 정적 분석 결과 `No issues found!`입니다.

40쪽의 사진 없는 재현에서 첫 입력 후 최초 실제 움직임은 16ms 간격의 시뮬레이션 펌프 기준 스와이프 6프레임, 버튼 7프레임이었습니다. 단순 페이지 점프가 아닌 실제 중간 애니메이션 상태를 확인했습니다. 이는 **테스트 프레임 수이며 실제 기기의 지연 시간·FPS 측정값은 아닙니다.**

먼 페이지의 사진 준비를 일부러 완료하지 않은 상태에서도 첫 넘김이 진행되는지, 준비 대기 중 빠른 손 떼기·취소, 배경 준비 중단·재개, 투명 표지 뒤로 캡처가 새지 않는지 확인했습니다. 기존 넘김 60개, 읽기 위치 복귀·편집·회전·컨트롤러 수명·사진 캡처·썸네일 관련 검증도 통과했습니다.

## 범위와 증거

작업 시작 시점의 소스 해시와 비교해 제품 코드 변경은 reader 2개 파일과 로컬 book_page_flip 4개 파일입니다. 새 회귀 테스트는 2개 파일입니다. 다른 기존 작업은 보존했습니다. `changes.patch`는 이 작업 시작 시점 대비 변경이며 저장소의 기존 미커밋 변경을 포함하지 않습니다.

- `verification.json`: 최종 결과와 테스트 수, 범위, 제약
- `logs/`: 최종 9개 묶음 결과·정적 분석·수정 전 실패 재현
- `baseline/`, `changes.patch`, `source-before.json`, `source-after.json`: 작업 전후 근거
- `probes/`: 이번 로컬 엔진 검증 도구. 경로·에셋은 해당 실행 환경에 종속됩니다.

실제 기기에서의 GPU 프레임 시간은 프로파일링하지 않았고 전체 앱 빌드·배포는 실행하지 않았습니다. 새로 요청한 사진이 아직 내려받기·디코딩 중이면 해당 넘김면 준비는 필요합니다. 전체 atlas 메모리 정책은 이번에 바꾸지 않았습니다.
