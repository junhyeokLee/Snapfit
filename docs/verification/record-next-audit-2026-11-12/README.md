# 기록에서 월간 앨범으로 — 다음 UX 개선

현재 Flutter 화면을 실행해 실제 사용을 방해하는 두 지점을 확인하고 수정했다. 새 디자인 방향을 다시 만들지 않고 기존 미리보기·사진 선택·앨범 제작 동작을 유지했다.

## 확인한 문제와 결과

| 지점 | 변경 전 | 반영 결과 |
| --- | --- | --- |
| 월간 앨범 제작 | 36장 중 9장을 골라도 모든 사진 아래까지 내려가야 만들기 가능 | 선택 수·나만 보기·만들기/추가/편집 행동을 하단에 유지. 선택한 위치에서 바로 실행 |
| 저장 완료 안내 | 전체 월 기록이 없는 직접 작성/임시 복구도 첫 장·월 합계를 단정 | 확인한 저장 사진 수만 안내. 전체 월 데이터를 가진 경로는 기존 첫 장·누적 안내 유지 |

18일×2장 합성 데이터에서 만들기까지 본문 스크롤은 390×844에서 **4,356px / 약 5.56화면**, 320×568에서 **3,972px / 약 7.82화면**이었다. 변경 후 사진 선택을 마친 위치에서 버튼을 보이기 위한 추가 스크롤은 두 크기 모두 **0px**다. 앨범 생성은 누르지 않았다.

## 검증

관련 기능 **100건 통과, 실패·건너뛰기 0건**: 월간/저장 30, 직접 작성·복구 12, 사진 규격 표시 8, 월간 사진 후보 8, 앨범 생성 데이터 42. 추가 사진 프레임 회귀 1건도 통과했다. 변경 후 네이티브 캡처 4개 시나리오를 통과했고, 위에서 채택한 이미지들을 직접 열어 확인했다.

- 최초 세 동작의 실패 검사를 먼저 확인했다. 독립 검토에서 찾은 키보드 가림과 다른 임시 복구 경로도 각각 1건·2건의 실패를 확인한 뒤 수정했다.
- 신규/기존 앨범, 선택 변경, 연속 요청, 실패 복구, 계정 변경, 수정된 표지·기존 페이지·사진 규격 보존을 검증했다.
- 키보드 300px을 둔 320×568·글씨 1.6배에서 실행 영역과 버튼 하단이 실제 키보드 경계 y=268 이하인지 검사했다.
- 현재 제작 정책과 다른 오래된 테스트 기대(원본 프레임 비율, 피드 글의 인쇄 페이지 생성)를 갱신했다. 열린 작성 화면으로 종료하는 세 테스트는 컨테이너를 검증 전에 해제해 자정 타이머를 정리했다. 제품의 사진 규격·피드/인쇄 정책·날짜 갱신 기능은 바꾸지 않았다.
- 변경 7파일 분석은 오류·경고 0개다. 기존 폰트 준비용 `createState` 조건 분기에 대한 `no_logic_in_create_state` 스타일 안내 2개는 남아 있다. 불필요한 구조 변경은 하지 않았다.

## 범위와 한계

실제 위젯·번들 폰트·사진과 메모리 저장소로 재현했다. 36장 fixture는 기존 사진 6개를 반복한 합성 데이터이며 개인 기록이 아니다. 390/320 월간 화면, 430×1100 저장 완료, 390 기존 앨범 상태를 독립 실행했다. 전체 가입→저장→서버 앨범 생성의 실계정 연속 실행은 아니다.

일부 오프스크린 캡처에서 고정 상단이 빠졌거나 초기 후보가 로딩 중인 파일은 채택하지 않았다. 동일 실행의 준비된 최종 캡처로 확인했다. 과거 기록 fixture와 현재 기기 월이 다른 journal 이미지는 전체 화면 UX 평가에서 제외하고 사진 프레임 회귀에만 사용했다. 제외 목록은 verification.json에 있다.

전체 앱 빌드·실기기·스크린리더·색 대비 수치·웹 실제 화면 검증은 하지 않았다. 실제 업로드·앨범 생성·초대·주문·결제·서버 변경도 하지 않았다. 검증용 임시 커널은 종료 후 삭제했다.
