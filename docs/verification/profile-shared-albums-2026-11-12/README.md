# 마이 · 공유 앨범 상태 개선

2026-11-12. 기존 전체 디자인 점검에서 아직 남아 있는 문제를 현재 코드와 실제 위젯 캡처로 다시 확인했다. 초대, 포인트 내역, 스토어의 이전 개선은 반복하지 않았다.

## 확인한 문제

`SocialProfilePersonalArea`가 목록 로딩과 실패를 모두 빈 목록으로 바꾸어, 두 상태에서 `0개의 함께 만든 앨범`을 표시했다. 갱신 중 보존된 성공 데이터도 버려 개수가 0으로 바뀌었다.

계정 교체 시 `HomeViewModel`은 이전 계정 자료를 지우기 위해 임시 빈 값을 넣는다. Riverpod가 이 값을 다음 로딩·오류에 보존할 수 있으므로 `hasValue`만으로 확인된 빈 목록을 판정해서도 안 된다.

| 상태 | 이전 | 개선 후 |
| --- | --- | --- |
| 첫 요청 대기 | 0개 | 앨범 확인 중 |
| 요청 실패 | 0개 | 실패 안내와 다시 시도 |
| 성공 목록 갱신 | 0개로 변경될 수 있음 | 마지막 확인된 개수 유지 |
| 계정 전환 후 임시 빈 목록 | 0개 | 대기·오류 상태 구분 |
| 성공한 빈 목록 | 0개 | 0개 |

실패한 행을 누르면 새 목록을 요청한 뒤 기존 공유 앨범 화면으로 이동한다. 기존 계정 확인, 중복 진입 방지, 늦은 응답 차단과 공유 앨범 필터는 유지한다. 새 카드나 설명 섹션은 추가하지 않았다.

`HomeViewModel`의 계정 교체 상태도 임시 빈 데이터를 가진 로딩으로 수정했다. 이전 자료를 지우면서 새 계정의 조회 future를 미완료로 유지하므로, 조회 전의 임시 빈 목록으로 화면이 먼저 열리는 것도 방지한다.

이 원자적 상태 전환에는 Riverpod 3의 `copyWithPrevious`가 필요하다. 현재 내부 API로 표시되어 해당 호출에만 이유와 분석 제외 주석을 남겼다. 의존성을 업데이트할 때 실제 HomeViewModel의 계정 변경·대기·실패·재시도 회귀 테스트로 호환성을 확인한다.

## 캡처와 검증 범위

- `before/`, `after/`: 실제 `SocialProfileScreen`, 앱 테마와 번들 글꼴을 사용한 네이티브 위젯 캡처.
- 가상 계정, 메모리 목록으로 로딩·실패·성공을 재현했다. 정상 390×844, 큰 글씨 1.8배의 어두운 320×844 화면을 확인한다.
- 실제 서버 요청이나 계정 변경, 공유·초대 발송은 하지 않았다. 연결 기기에서의 직접 조작 검증을 뜻하지 않는다.
- 첫 회귀 검증에서 신규 4개 중 3개가 기존 오표시로 실패하는 것을 확인한 뒤 수정했다. 로그는 `logs/red.log`에 보존했다.
- 기존 사진 테스트의 세로 프레임 기대값은 현재 정사각 앨범 기본 규격과 달랐다. 기대값을 1로 갱신하고 원본을 `BoxFit.contain`으로 보존하는 검증은 유지했다. 제품의 사진 비율 코드는 수정하지 않았다.

최종 검증 결과와 소스 해시는 `verification.json`, 실행 로그는 `logs/`, 캡처 코드는 `probes/`에 보존한다. SDK 캐시 쓰기 없이 설치된 Flutter 테스트 엔진과 Dart frontend로 실행했으며, 앱 전체 빌드·설치·상시 서버 실행은 하지 않았다.

관련 회귀 **93개**, 캡처 **6개** 통과. 변경한 제품·테스트와 캡처 코드 5개 파일의 정적 분석은 `No issues found!`다. 독립 코드 리뷰에서 나온 계정 변경 경계조건을 반영했고 추가 blocking은 없었다.

정상 성공 상태의 화면은 수정 전후 픽셀이 동일했다. 기본 화면의 변화는 로딩 안내 텍스트와 오류 행의 안내·아이콘에 한정된다. 큰 글씨에서도 오류 안내를 한 줄로 읽을 수 있도록 `확인 실패 · 다시 시도`로 줄였다.
