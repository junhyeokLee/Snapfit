# 한 페이지 초점 리더 검증

승인한 `album-spread-turn.html`의 실제 펼침 관계를 Flutter 읽기 화면에 적용했다.
세로에서는 한 페이지와 옆 장의 작은 부분을 보이고, 가로에서는 전체 펼침을 유지한다.

## 결과

- 390px 세로 화면에서 한 페이지 폭 171px → 342px. 저장된 정사각형·4:3·5:4 비율 유지.
- 같은 펼침의 왼쪽→오른쪽은 카메라 이동, 오른쪽→다음 왼쪽은 실제 종이 넘김.
- 2쪽의 앞면/3쪽의 뒷면 매핑과 실제 텍스처 좌표의 읽기 방향을 검사했다.
- 제본선은 왼쪽 장의 오른쪽, 오른쪽 장의 왼쪽에 놓인다. 정지한 고해상도 페이지
  위에도 제본 음영이 보인다.
- 큰 편집 버튼과 상시 썸네일을 간소화했다. 편집은 메뉴에서, 쪽 목록은 ‘전체 쪽’에서 연다.
  협업 멤버 접근과 가로 펼침의 기존 조작은 유지한다.
- 명시적 페이지 선택은 회전·빠른 연속 선택 중에도 유지된다. 직접 드래그 취소는 시작 쪽으로 돌아온다.

수정한 제품·테스트 5개 파일의 정적 분석은 `No issues found!`다. 독립 읽기 검토에서
발견한 요청 중 회전 문제는 실제 실패를 확인하고 수정했으며, 추가 재잡기 취소 회귀도 통과했다.
최초 크기·쪽 이동 회귀와 회전 회귀의 실패 로그, 최종 8개 테스트 묶음의 출력은 `logs/`에 있다.
소스 해시와 검사별 결과는 `verification.json`에 기록했다.

## 시각 자료

`page-turn.mp4`는 실제 원본 템플릿 ‘약속을 묶은 책’의 2쪽→3쪽 넘김이다.
Flutter 네이티브 위젯에서 기록한 37개 프레임을 30fps로 묶고 시작·끝에 정지 시간을 추가했다.
글자·사진·종이 형태는 생성하거나 합성하지 않았다.

소프트웨어 캡처가 일부 고정 텍스트·아이콘을 누락하는 현상이 있어 영상에는 검증한
책 영역만 담았다(원본 780×1688에서 x0/y400/w780/h800). `screens/`의 전체
프레임은 지면 검수용이며 전체 UI의 완성 화면을 증명하는 자료로 사용하지 않는다.
표지의 곡면 사진은 RawImage 대신 AlbumSpineImagePainter가 그리므로, 캡처 준비 검사는
해당 painter가 가진 디코딩 이미지를 함께 확인했다.

전체 앱 빌드·설치·상시 서버·운영 데이터 변경은 수행하지 않았다. 검증은 실제 Flutter 위젯과
네이티브 소프트웨어 렌더러에서 수행했으며, 기기에서의 체감 프레임 속도 측정은 포함하지 않는다.
