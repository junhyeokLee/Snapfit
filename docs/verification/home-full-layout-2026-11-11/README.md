# 홈 전체 배치 점검 — 2026-11-11

## 결론

월간 달력을 맨 앞에 두는 방향과 큰 앨범 한 권 아래에 작은 선택 목록을 두는 방향은 유지한다. 우선 개선할 배치는 **작은 화면에서 오늘 기록 진입이 늦게 나오는 점**이다. 기록 영역과 내 앨범 사이의 거리도 측정했지만, 중간 영역은 각각 목적이 있고 실제로 함께 보이므로 재배치는 선택 사항으로 남긴다. 이번 점검에서는 제품 코드를 수정하지 않았다.

## 현재 순서와 제안

현재: 월간 기록·오늘 기록 → 모아둔 순간 → 월간 앨범 엮기 → 이어서 만드는 이야기 → 나의 앨범 → 작은 앨범 선택 목록.

현재 순서를 우선 유지한다. 앨범을 더 앞에서 강조할 필요가 확인되면 비교할 대안은 월간 기록·오늘 기록 → 나의 앨범·작은 선택 목록 → 모아둔 순간·월간 앨범 엮기다. 이때 미완성 앨범의 이어 만들기는 해당 앨범 영역과 묶고, 별도 생성 초안의 복구 경로는 유지한다. 새 앨범 버튼을 크게 만들 필요는 없다.

| 우선순위 | 확인한 문제 | 개선 제안 | 근거 |
| --- | --- | --- | --- |
| 1 | 높이가 짧은 화면에서는 오늘 기록 행동이 처음에 잘 드러나지 않는다. | 작은 화면에서도 월 제목 가까이에 오늘 기록 진입을 둔다. 달력 전체와 기존 사진을 줄여 맞추는 방식은 피한다. | 320×568에서 콘텐츠 표시 영역은 높이 362px. 오늘 기록 버튼은 화면 y=708~756에 있어 첫 화면에 보이지 않는다. 오늘 날짜 타일도 하단 탐색 영역 위로 윗부분만 보인다. 스크롤하면 기록할 수 있으므로 입력 불가 결함으로 분류하지 않는다. |
| 보류 | 큰 앨범을 보기 전 최근 사진, 앨범 엮기, 이어 만들기가 모두 나온다. | 현재 유지. 앨범 강조가 더 필요해질 때 위 순서를 비교한다. 중간 영역을 삭제하거나 무조건 축소하지 않는다. | 390×844에서 모아둔 순간 시작부터 나의 앨범 제목까지 467.8px이나 중간 세 영역이 한 화면에 함께 보이고 목적이 다르다. 상단 앨범 목록 바로가기도 있다. 거리만으로 사용성 문제를 확정할 근거는 부족하다. |

## 유지할 배치

- **월 달력과 보상 진행률:** 390×844 첫 화면에서는 6주 달력과 오늘 기록 버튼이 모두 보인다. 매일 기록을 쌓는 목적에 맞으므로 달력을 축소하거나 접지 않는다.
- **큰 앨범 + 아래 작은 선택 목록:** 390×844에서 스크롤을 맞추면 큰 앨범 영역 366.6px와 선택 목록 95.95px가 함께 들어간다. 선택한 앨범을 크게 보여주는 구조를 유지한다. 320×568에서는 두 영역을 순서대로 스크롤해 보는 것이 자연스럽다.
- **사진 비율:** 이번 실제 템플릿/로컬 사진 표본에서는 가로세로가 강제로 늘어난 모습은 확인하지 않았다. 모든 사진 비율이나 전체 템플릿을 검증했다는 의미는 아니다.
- **상단 도구:** 앨범 목록, 작은 새 앨범 버튼, 알림의 배치는 유지한다.

## 캡처와 수치

실제 `HomeScreen` 전체를 띄우고 각 장면을 스크롤 0부터 새로 시작했다. 화면 논리 크기는 390×844와 320×568, DPR 2, 안전 영역 위 24px/아래 34px다. 기록 날짜는 테스트용 2026-11-18, 6주에 걸친 11월 달력, 기록 전 17/30일 및 기록 후 18/30일, 앨범 3권을 사용했다. 실제 카탈로그의 표지 레이어와 번들 사진을 사용했고 계정·저장소·알림 등은 메모리 대역으로 대체했다. 업로드, 주문, 결제, 서버 변경은 없다.

**캡처 한계:** `03-album-focus`와 `04-album-selector` PNG에는 소프트웨어 오프스크린 렌더링에서 고정 헤더가 빠지고 본문 좌표가 위로 이동하는 현상이 남아 있다. 해당 4개 이미지는 전체 화면의 위치·겹침·헤더 상태를 판단하는 근거에서 제외한다. 앨범 내부의 시각 구성 참고에만 사용한다. 별도 RenderBox 수치는 헤더 y=24~104와 콘텐츠 y=104 이후를 일관되게 보고한다. 이 캡처 차이를 앱 결함으로 보고하지 않는다. 실제 기기에서의 스크롤 화면 확인은 아직 하지 않았다.

`*-stepN-layout-metrics.json`에는 최초 위치부터 해당 장면까지의 실제 위젯 좌표가 기록돼 있다. `visibleHeight`는 **스크롤 영역과의 교집합**이므로 고정 헤더/하단 탐색 영역의 값이 0인 것은 숨겨졌다는 뜻이 아니다.
