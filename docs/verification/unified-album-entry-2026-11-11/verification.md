# 기존 편집기 통합 진입 — 적용·검증

2026-11-11. 기존 편집기를 유지해 달라는 최신 사용자 피드백과 실행 승인을 반영했다.

## 반영한 동작

1. **디자인 선택 → 설정 → 기존 편집기 → 저장.** 설정의 ‘앨범 편집하기’에서 표지·내지 편집기로 바로 들어간다. 필수 사진 채우기, 별도 표지 편집, 생성 전 별도 전체 확인을 거치지 않는다.
2. **기존 편집 화면 유지.** 상단 페이지 목록, 큰 캔버스, 선택 대상에 따른 도구, 페이지별 undo/redo를 보존했다. 새 편집기 이미지 시안은 적용하지 않았다.
3. **여러 장 넣기는 선택 도구.** 빈 사진 슬롯이나 남은 사진이 있을 때 더보기에서 연다. 작업본의 ‘편집기에 적용’만 반영한다. 취소·오래된 작업 적용은 원본을 바꾸지 않는다. 페이지의 별도 배경색도 메인·썸네일·사진 구도 문맥·배치 미리보기에 전달한다.
4. **복구와 사진 목록 보존.** 생성 attempt를 먼저 기록하고 같은 요청 ID로 재시도한다. 연결 checkpoint 기록 전에는 편집기로 이동하지 않는다. 미배치 사진은 생성 화면의 dispose와 격리한 복사본으로 넘기고, 연결 초안에 함께 기록한다. 큐만 바뀐 경우에도 저장 중·실패 후 조용히 종료되지 않으며, 명시적 버리기는 진입 당시 문서와 큐를 복원한다.
5. **계정과 문서 경계.** 선택 도구의 소유 Navigator를 제거해 사진 선택·crop 하위 화면까지 닫는다. 다른 계정·앨범·규격·문서로 바뀐 작업은 적용하지 않는다.

## 확인 범위와 남은 제약

- 일반 Flutter CLI의 캐시·소켓 제한 때문에 설치된 frontend compiler와 `flutter_tester`의 동일 테스트 본문을 직렬 실행했다. 무거운 작업은 항상 한 프로세스씩 수행했다. 전체 앱 빌드·배포·실기기·브라우저 실행 결과는 아니다.
- **웹 전용 AI 19건은 실행 검증에서 제외했다.** 작업 시작 백업부터 AI 모드 진입은 `kIsWeb && initialAiMode`에 한정돼 있었고 네이티브 시작 화면에는 AI CTA가 없었다. 테스트를 통과시키려고 제품의 AI 진입을 새로 열지 않았다. 테스트는 공개 `/create/ai` 진입 인자로 이전하고 네이티브 제외 사유를 명시했다. 실제 브라우저 검증은 남아 있으며, 공용 `ai_template_v3_fixture.dart`의 `dart:io` 동기 파일 읽기도 웹 호환 작업이 필요하다. 제외 19건을 통과 수에 더하지 않았다.
- 페이지 배경색 회귀를 보완한 뒤 관련58개 테스트와 캡처6개를 다시 실행했다. 기존 편집기·저장 화면 PNG 9개는 보완 전후 SHA-256이 모두 같았다. 배경색을 지정하지 않은 기존 렌더링은 유지했다.
- 소프트/하드커버를 주문 단계로 옮기는 일은 이번에 적용하지 않았다. 현재 선택 기능을 유지하고 주문 흐름을 확인한 후 별도로 정리한다.
- 저장 후 앨범 화면은 소스를 변경하지 않았다. 다음 점검 결과는 `../saved-album-followup-2026-11-11/README.md`: 큰 앨범과 비율을 유지하고, 설명 축소와 미완성 앨범의 ‘이어서 편집’ 노출을 우선 제안했다.
