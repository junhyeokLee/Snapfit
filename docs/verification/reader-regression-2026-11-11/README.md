## 실패 원인

### 1. 현재 화면과 다른 버튼 문구

테스트가 `앨범 크게 보기`를 찾았지만 실제 버튼과 작업 전 코드의 문구는 `앨범보기`였다. 동일한 오래된 기대값 두 곳을 수정했다. 한 곳은 소유자/보기 전용 반복 검사에도 사용된다. 터치 영역, 글자 잘림, 접근성, 선택한 앨범, 중복 진입에 대한 검사는 유지했다.

### 2. 테스트 사이에 남은 비동기 준비 작업

나머지 4건은 리더 경로 자체가 사라진 문제가 아니었다. 리더는 존재했지만 첫 페이지의 이미지 준비가 멈춰, 전체 페이지 캡처 후에 생기는 `BookFlip` 위젯이 생성되지 않았다. 단독 실행은 4/4 통과했으나 앞선 접근성·인쇄·80쪽 테스트와 연속 실행하면 4건이 모두 실패했다. 추가 대기를 해도 준비가 끝나지 않았다.

이번 네이티브 검증 런타임은 `UNIT_TEST_ASSETS`가 없는 `flutter_tester` 진입으로, 자산 목록을 실제 비동기 엔진 응답으로 읽는다. 테스트별 가상 시간에서 처음 시작한 `AssetManifest.bin`의 미완료 Future가 전역 번들 캐시에 남으면 다음 테스트도 같은 Future를 기다린다. 이때 이미지 캐시에 접근하기 전이므로 `pendingImageCount=0`이면서 이미지 준비가 멈출 수 있었다.

자산 목록을 미리 준비한 후에는 이전 테스트의 미완료 이미지 스트림이 재사용되는 두 번째 문제가 드러났다. 이미지 캐시 정리와 자산 목록 사전 준비를 함께 적용해야 연속 실행이 통과했다.

## 적용한 수정

수정 파일은 `test/widget/home_book_depth_test.dart` 하나다.

- 테스트별 가상 시간이 시작되기 전에 폰트와 `AssetManifest`를 준비한다.
- 각 테스트 시작 시 이미지 캐시의 일반 항목과 live 항목을 모두 정리한다.
- 같은 테스트 안에서 화면을 그린 뒤 추가로 사진을 준비할 때도 미완료 캐시 키만 제거하고 실제 비동기 시간에서 `precacheImage` 완료를 기다린다. 이전 전체 실행이 멈췄던 책장 구성 검사도 이 방식으로 완료됐다.
- 오래된 버튼 문구 기대값 두 곳을 현재 문구로 맞췄다.

대기 횟수를 늘리거나 assertion을 제거하지 않았다. 실제 앨범·사진·페이지 넘김·회전·소유자/보기 전용 동작을 검사한다. 제품 코드와 로컬 `book_page_flip` 패키지는 변경하지 않았다. 원인 추적에만 쓴 임시 로그는 패키지 원본과 바이트 단위 일치 여부를 확인해 복구했다.
