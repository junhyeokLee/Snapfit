# 읽기 화면 연속 넘김 반응 개선

앞선 수정은 첫 진입·첫 입력 반응을 개선했습니다. 이번에는 넘김 중 다음 입력이 버려지던 경로를 수정했습니다.

## 실제 원인

세로 읽기의 버튼은 넘김 중 비활성화됐고, 실행 경로도 동작 중 입력을 바로 버렸습니다. 같은 펼침 안의 카메라 이동은 재잡기 자체가 막혔으며, 책 넘김 막바지의 같은 방향 새 스와이프도 이전 종이를 다시 잡았습니다. 연속 동작을 붙인 뒤에는 부모 화면이 되돌려주는 현재 쪽수가 새 선택으로 오인되어 다음 동작을 취소하는 문제도 재현했습니다.

## 적용한 동작

- 버튼은 넘김 중에도 다음 입력을 받습니다. 새 입력이 오면 현재 동작의 남은 정착 시간을 **80ms**로 줄이고, 완료 직후 다음 방향으로 이어갑니다. 중복 입력이 정착 타이머를 계속 다시 시작하지 않습니다.
- 대기 입력은 최신 방향 하나를 보존합니다. 빠른 다음→이전 변경이 반영되며, 오래된 연타가 손을 뗀 뒤 길게 자동 재생되지 않습니다.
- 같은 펼침 안의 카메라 이동도 손가락으로 바로 다시 잡아 반대로 되돌릴 수 있습니다. 재잡은 순간의 진행률에서 이어가므로 위치를 0으로 초기화하지 않습니다.
- 새 터치 시작 당시 완료 방향으로 **80% 이상 진행**한 페이지에서 같은 방향으로 새 스와이프하면, 이전 착지를 정리하고 현재 손가락 이동을 다음 지면에 연결합니다. 초기 진행 구간·반대 방향·취소 중인 동작은 기존 재잡기와 되돌리기를 유지합니다.
- 부모 화면에 알린 쪽수의 다음 프레임 반영은 한 번만 구분해 새 연속 동작을 취소하지 않게 했습니다. 명시적으로 페이지 목록에서 현재 쪽을 선택해 진행 중인 동작을 취소하는 계약은 유지합니다.
- 표지·마지막 쪽과 가로 읽기에서도 이동 중인 목적지를 기준으로 반대 버튼을 허용합니다. 다른 화면으로 이동한 뒤에는 대기 입력이 새 넘김을 시작하지 않습니다.

단일 입력의 500ms 시간 곡선, 종이 곡면, 표지↔내지 대응, 사진 품질 정책은 유지했습니다.

사진이 준비된 40쪽 테스트에서 두 번째 입력 후 다음 동작의 실제 중간 움직임이 16ms 간격 펌프 8회(128ms) 안에 나타나는 것을 검사했습니다. 이는 테스트 시뮬레이션 기준이며 실제 기기의 지연 시간·FPS 측정값이 아닙니다. 새 사진의 다운로드·디코딩 대기는 여전히 필요할 수 있습니다.

`logs/repeat-red.log`는 수정 전 6개 연속 동작 실패, `logs/parent-echo-red.log`는 부모 연동 후 5개 실패, `logs/boundary-red.log`는 양 끝 반전 2개 실패를 보존합니다. 나머지 로그는 최종 결과입니다. `changes.patch`와 `baseline/`은 이번 후속 작업 시작 시점 대비 변경이며 이전 미커밋 작업을 포함하지 않습니다. `verification.json`과 소스 해시로 최종 상태를 확인할 수 있습니다.

실제 기기에서 프레임률을 프로파일링하거나 전체 앱을 빌드·배포하지 않았습니다.
