2026-11-16 SnapFit 디자인·UI/UX 추가 개선

실제 홈·설정·계정·디자인 상세를 먼저 캡처하고, 콘텐츠와 주요 동작이 분명하게 보이도록 화면을 개선했다. 기존 teal 브랜드, 사진·앨범 중심 구성과 Flutter/Riverpod 구조를 유지했다.

이번 방향은 [Google Material 3 Expressive의 공식 연구](https://design.google/library/expressive-material-design-google-research)가 강조하는 주요 행동의 시각적 구분과 관련 항목 그룹화, 콘텐츠에 맞는 크기·형태·강조 원칙을 참고했다. 효과 수치는 아래 로컬 화면 측정이며, 해당 연구의 사용자 성과를 스냅핏의 성과로 주장하지 않는다.

실제 위젯 캡처도 기본 9개 시나리오와 큰 글씨 기록 부분의 추가 촬영을 통과했다. 수정 전 17장과 수정 후 18장을 보관했다. 같은 크기·동일 상태의 화면을 전후 비교에 사용했으며, 추가로 스크롤해 촬영한 기록 부분은 수정 후 화면으로만 구분했다. 수정 제품 5개 파일과 테스트 7개 파일 분석은 `No issues found!`, 포맷·공백 검사도 통과했다.

검토에서 발견한 큰 글씨의 사진 버튼 넘침과 홈 앨범 제목 행의 정렬을 보완했다. 테스트는 사진 준비를 실제 시간 대기와 프레임 진행으로 나누어 끝없는 이미지 대기를 막고, 로컬 사진의 ID·개수·디자인을 보존했다. 전역 텍스트 탐색은 실제 지표 영역으로 한정했다. 소재 응답은 활성 상태와 서버 가격을 명시하고, 지연 생성되는 스토어 카드는 실제 스크롤로 생성한 뒤 이동을 검증했다. 가격·보유권을 바꿔 테스트를 통과시키지 않았다.

주간 달력·내 앨범의 전체/즐겨찾기 구조·하단 메뉴 정책과 기존 표지 열기를 보존했다. 새 상품·가격·운영 데이터·의존성·인쇄·결제 로직은 추가하지 않았다.

검증은 로컬 Flutter 엔진과 계정·저장소 대역에서 수행했다. 실제 기기와 웹 브라우저 실행, 화면 읽기 프로그램 전체 검증, 운영 결제·앱 전체 빌드·배포는 수행하지 않았다. 캡처의 일부 Pretendard 이름에는 NotoSansKR을 연결했으며, 디자인 상세의 판매 폰트는 번들 FontManifest에서 로드했다. 앱 전체 테스트나 완전한 접근성 준수를 주장하지 않는다.
