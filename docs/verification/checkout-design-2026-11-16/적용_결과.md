# 인쇄 주문·결제 화면 디자인 적용 결과

주문 화면과 결제 완료 화면의 표시 구조를 개선했다. 검증용 앨범·주문 데이터로 실제 Flutter 위젯과 번들 폰트를 렌더했으며, 실제 결제·제작·배송 요청은 실행하지 않았다.

## 적용

- **앨범 요약 카드:** 검토가 끝난 기존 snapshot에서 표지·규격·내지 수·주문 수량을 표시한다. 기존 표지 렌더러를 재사용하며 문서 Map/String을 모두 지원한다. 검토 내용이 바뀌거나 조회가 실패하면 이전 표지를 남기지 않는다. 표시를 위해 주문 snapshot을 추가 조회하지 않으며 표지 데이터는 결제 판정에 사용하지 않는다.
- **주문 금액 카드:** 제작 구성·추가 빈 페이지·총액·확인된 기본 배송비 포함 여부를 한곳에 표시한다. 기존 가격 상태·문구·금액 조건을 보존했다. 좁은 화면과 큰 글씨에서는 세로로 배치한다.
- **동의 영역:** 세 항목을 한 영역에 묶고 제목을 요약했다. 확인 내용·정책·주문제작 전문을 펼쳐볼 수 있고 미리보기 복귀는 바로 누를 수 있다. 주문제작 제한의 조건과 제작 전 취소 요청·불량·오배송 권리는 기본 화면에도 표시한다. 기존 별도 동의 3개와 원문·버전은 유지하며 상세 펼치기로 선택값이 바뀌지 않는다.
- **완료 화면:** 확인된 결제금액·주문번호·현재 상태를 우선 표시한다. 알려진 상태와 확인된 이력에만 다음 예정 단계를 안내한다. 전체 8단계는 펼쳐보며, 단계 완료는 기존 타임스탬프 조건으로 판단한다. 취소·환불 요청·미확인·조치 필요·조회 실패에는 다음 제작 단계를 예고하지 않는다.

## 검증

| 범위 | 통과 |
| --- | ---: |
| 주문·결제 위젯 | 35 |
| 완료·진행 상태 | 10 |
| 동의 payload 계약 | 2 |
| 인쇄 결제 서비스 | 19 |
| 포인트 결제 반응형 회귀 | 28 |
| 인쇄 주문 회전·반응형·접근성 회귀 | 46 |
| **관련 테스트 합계** | **140** |
| 실제 위젯 캡처 테스트 | 9 |

새 동작 9건은 구현 전 실패를 확인했다. 구현 후 관련 테스트 140건과 캡처 9건이 통과했고 PNG 15장을 확인했다. 변경 파일 5개의 정적 분석은 문제없으며 diff whitespace 검사도 통과했다.

320×568, 390×844, 648×320, 740×360, 844×390 화면과 라이트·다크, 최대 1.8배 글씨, 키보드·회전·동의 이동을 검증했다. 검증 중 상세 펼침과 스크롤 저장 키 충돌을 고유 PageStorageKey로 해결했고, 매우 짧은 가로 화면의 확인 문구를 요약해 체크 영역을 누를 수 있게 했다. 지연 생성되는 주문 취소 링크·저장된 배송지·전체 단계는 실제 스크롤·펼치기 후 검사하도록 테스트를 맞췄다.

독립 리뷰에서도 금액·동의 3개·전문 버전·계정 확인·결제 복구에 변경이 없음을 확인했다. 결제·주문 서비스 및 서버·운영 DB에는 이번 작업으로 변경하지 않았다.

## 확인 범위

로컬 headless Flutter 엔진에서 실제 위젯을 재현했다. 실기기 Android/iOS, 브라우저 결제 SDK, 실제 PG 결제·환불·인쇄 발주·배포는 이번 검증에 포함하지 않았다. 이미지는 검증용 앨범과 주문 데이터이며 고객 거래 증빙이 아니다.
