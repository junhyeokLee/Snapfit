## 2026-10-21 무료 AI 영속 작업 운영 반영

무료 AI 선택형 요청·기기 메모·앱 복귀·긴 대기·이미 결제한 초안 복구를

`main.d7c938f222fd8b6a11c1.dart.js`, 부트스트랩은
`flutter_bootstrap.b0835608b6fba5d76be5.js`이며 원격 SHA256이 로컬과 같다.
HTML이 새 부트스트랩을 가리키며 공개 카탈로그가 정상 표시됨을 확인했다.
기존 로그인·푸시·결제 차단·검색 제외와 캐시 헤더를 유지한다.

서버 `ai-album-draft` v43(17개 파일)과 별도 `ai-template-worker` v2(16개
파일)의 운영 소스가 일치한다. 고객 엔드포인트는 JWT·현재 사용자 확인,
worker는 AI 전용 HMAC·일회용 nonce로 보호한다. 안전한 선택값 작업 정책과
AI 전용 Cron은 활성화했고 원문 v3 경로는 차단한다. Gemini 3.8 Flash 무료
전용이며 유료 모델로 전환하지 않는다. 실제 합성 시험 4회는 일시 오류로
완성되지 않았으며 예약 재시도·저장·무차감을 확인했다. 설치 앱은 별도의
스토어 업데이트가 필요하다. 증빙은
`docs/verification/ai-free-resumable-production-2026-10-21.json`을 따른다.

## 2026-10-20 운영 반영

`python3 tool/build_web.py --output build/review-web`로 검증한 릴리스 829개 파일을 Firebase `snapfit-c719d` Hosting에 게시했다. 실제 공개 주소는 `https://snapfit-c719d.web.app`이며 `main.c7c510491cc8168a4d17.dart.js`와 `flutter_bootstrap.494c545fdae66049bb33.js`의 원격 SHA256이 로컬과 같다. 공개 검색, 판매 중 디자인의 가격·상세·이용 안내, 로그인 연결을 실제 브라우저에서 확인했다. OAuth·푸시 공개 설정, 결제 차단, 검색 제외·캐시 헤더는 유지한다.

별도 미리보기 파일은 생성하지 않았다. 배포용 빌드·검사 캐시는 확인 후 정리하며 원본 소스·앱 자산·기존 골든을 보존한다. AI 서버는 v39를 운영에 반영했으나 무료 Gemini의 장애·한도 때문에 새 완성 책 검증은 실패했으며, 개인정보·v3 고객 개방 차단을 유지한다. 설치 앱의 스토어 업데이트는 이 웹 배포에 포함되지 않는다. 상세 증빙은 `docs/verification/ai-gemini-live-production-2026-10-20.json`을 따른다.

2026-10-20 저장공간 정리에서 로컬 `build/`와 재생성 가능한 미리보기·컴파일 캐시를 삭제하고 8136 미리보기 서버를 종료했다. 구현 소스와 의존성·SDK는 보존했다. 다음 웹 확인 시 `python3 tool/build_web.py`로 새 빌드를 만든 뒤 서버를 연다. 아래의 과거 캡처·빌드 성공 기록은 당시 검증 결과이며 현재 파일의 존재를 뜻하지 않는다.

## 2026-10-20 공개 상품 정보·검색 복구 보완

- 공개 디자인의 목록과 상세는 공개 상품 카탈로그의 가격만 표시한다. 무료는 등록된 0P로 확인하며 가격 미등록·판매 준비·조회 실패를 구분한다. 상세에 실제 내지 쪽수·디자인 모양·같은 비율의 인쇄 규격과 이용 범위를 제공한다. 공개 조회로 보유 여부·잔액·사용 권한을 요청하지 않으며, 로그인 후 기존 최종 이용 조건 확인을 거친다.
- 검색 결과가 없으면 검색어와 주제를 한 번에 초기화하거나 실제 카탈로그에 있는 다른 주제로 이동한다. 카탈로그 자체가 비어 있는 상태를 따로 안내한다. 공개 탐색과 웹 카탈로그의 결과 수는 입력이 500ms 안정된 뒤 화면읽기에 전달하며 포커스를 이동하지 않는다. 검색어나 주제는 주소와 로그인 복귀 기록에 추가하지 않는다.
- 이번 후속 작업은 fixture 기반 앱·Chrome 검사로 확인한다. 별도 미리보기·영상·웹 릴리스 빌드는 만들지 않으며 최종 기록은 `docs/verification/design-medium-three-2026-10-20.json`을 따른다.

## 2026-10-20 공개 탐색·작업 복귀·적응형 편집 개선

- 첫 방문자는 `/`에서 서비스 설명과 공개된 표지·내지를 둘러본다. `/designs`와 공개 템플릿 상세도 로그인 전에 볼 수 있다. 공개 탐색에는 번들로 제공한 정식 공개 템플릿만 사용하며 계정이나 고객 문서를 만들지 않는다. 음수 템플릿 ID는 공개 카탈로그에서 다시 확인하고, 앨범·편집·주문 ID의 인증과 접근 권한은 기존대로 검증한다.
- `/login`으로 로그인하며, 로그인 이후 기본 화면은 최근 수정순의 내 앨범 작업공간이다. 템플릿 상세에서 로그인하면 고른 디자인으로 복귀한다. 앱도 로그인 화면에서 먼저 둘러볼 수 있고 선택한 공개 템플릿 ID를 현재 실행 세션에만 보관한다.
- 웹 로그인 복귀는 정규 내부 경로만 15분간 보관하고 한 번 소비한다. 브라우저 저장 실패에는 현재 탭의 메모리를 사용하며, 저장·소비·삭제를 직렬화한다. 복귀 경로를 읽은 후에도 실제 목적지의 검증된 계정을 다시 확인한다.
- 일반 페이지의 넓은 헤더는 브랜드·탐색을 같은 줄에 배치한다. 좁은 창과 큰 글자는 전체 메뉴에서 모든 목적지를 명시적으로 제공한다. 좁은 카탈로그는 검색·주제를 먼저 표시하고 필터·정렬을 접는다. 스토어의 중복 웹 검색 바로가기는 제거하고 인라인 검색을 사용한다.
- 편집 속성은 좁은 창에서 아래, 중간 폭에서는 옆에 배치하며 작품 위를 덮지 않는다. 짧은 창과 키보드가 열린 상태에는 작품 크기를 확보한 채 스크롤한다. 사진 교체·자르기·글 편집은 이름을 표시하고 정밀 수치 입력은 접힌 고급 조정에 둔다.
- 좁은 웹의 아래 속성 패널은 손잡이 드래그·높이 버튼·위아래 방향키·Home/End로 조절한다. 높이 선호는 화면 상태에만 보관하며 창·키보드에 맞춰 일시 제한한 후 복원한다. 짧은 가로 창에서는 헤더를 압축해 작품과 패널까지 스크롤할 수 있다. 문서 좌표와 캔버스 배율은 유지한다.
- 저장은 계정 저장과 이 브라우저 임시 보관을 구분한다. 성공한 저장 시각만 표시하고 패널 전환 중 캔버스 배율을 유지한다. 저장·이탈 보호와 서버 가격·소유권·주문 가능 상태는 기존 동작을 사용한다.
- 앱과 웹의 주요 버튼은 동일한 `onAccent` 의미 색을 사용한다. 템플릿 카드는 키보드 조작·포커스·선택 상태를 제공한다. 실제 책·표지·내지의 원본과 저장 문서 좌표는 변경하지 않는다.

이 단계의 검수 기록은 `output/design-improvements-2026-10-20/verification.json`에 보존했다. 이후 패널 수동 조절·제작 방식별 도형 예시·앨범 상태 보완은 `docs/verification/design-completion-2026-10-20.json`을 따른다. 후속 검증은 새 미리보기 갤러리·영상·릴리스 빌드를 만들지 않고 자동 검사로 수행한다. 이전 캡처는 삭제 전 기록이며 현재 구현의 증빙으로 혼용하지 않는다.


별도 프로젝트 없이 기존 Flutter 앱의 web 타깃을 사용합니다. Supabase의 계정·앨범·Storage·주문 기능을 앱과 공유합니다. 새 유료 서비스는 사용하지 않습니다.

`WebNavigationScope`가 웹 전역 메뉴를 Router로 연결합니다. `/#/designs`, `/#/library`, `/#/notifications`를 추가하며, 브라우저 메뉴 이동도 기존 문서의 저장 확인을 거칩니다. 같은 섹션의 상세 화면에 있더라도 전역 메뉴를 누르면 해당 목록으로 이동할 수 있도록 현재 최상위 경로를 구분합니다.

`showWebAwareDialog`는 창 크기에 맞는 중앙 Dialog의 공통 틀입니다. 네이티브 전용 sheet는 기존 분기로 보존합니다. 사진·문서의 내용과 좌표, 권한·초대·원본·견적 검증은 화면 구성과 분리합니다.

## 로그인 설정

웹의 Google·카카오 로그인은 Supabase OAuth를 사용합니다. 모바일의 네이티브 로그인은 유지합니다. 복귀한 세션은 Auth 서버에서 검증한 뒤 사용자 프로필과 동기화합니다.

현재 Supabase 허용 목록에는 `http://127.0.0.1:7357/?auth_callback=1`, `http://localhost:7357/?auth_callback=1`, 네이티브 `snapfit://auth/callback`과 두 로컬 호스트의 가변 숫자 포트를 지원하는 개발 패턴이 등록돼 있습니다. 예를 들어 `http://localhost:59841/?auth_callback=1`도 허용됩니다. 고정 Site URL은 첫 번째 개발 주소로 유지했습니다. 실제 웹 도메인을 정하면 해당 HTTPS 주소의 `/?auth_callback=1`을 허용 목록에 추가하고 기본 Site URL을 운영 주소로 바꿔야 합니다. 임의 외부 복귀 주소는 앱이 거부합니다. 제공자 콘솔의 콜백 주소는 Supabase Auth 주소이며 앱 주소와 구분합니다.

2026-10-16 추가 제보의 실행 주소는 `http://localhost:59841/`로 확인됐습니다. 이 실행은 7357 정적 게시본과 별도이며, 앱은 `http://localhost:59841/?auth_callback=1`로 OAuth 복귀를 요청합니다. 제보 당시 확인한 허용 목록에는 이 주소가 없었습니다. 허용되지 않은 주소가 Site URL로 대체되면 호스트·포트가 달라져 원래 브라우저 저장소의 PKCE 확인값을 사용할 수 없게 됩니다. 당시에는 고정 주소 실행 구성을 추가했고, 이후 아래 가변 포트 서버 설정을 별도로 반영했습니다. 사용자가 실패한 순간의 실제 반환 경로·계정 상태는 브라우저 제어 서비스 오류와 커넥터 권한 제한으로 직접 재확인하지 못했으므로 그 첫 실패의 원인은 확정하지 않았습니다. [Supabase 복귀 주소](https://supabase.com/docs/guides/auth/redirect-urls), [PKCE 저장소 제약](https://supabase.com/docs/guides/auth/sessions/pkce-flow)

같은 날 사용자의 추가 요청으로 Supabase Management API의 `uri_allow_list` 한 필드만 PATCH했습니다. 기존 3개 주소와 Site URL을 보존한 채 `localhost`·`127.0.0.1`의 숫자 1~5자리 포트와 정확한 `/?auth_callback=1`에 대응하는 10개 패턴을 추가했습니다. 임의 호스트로 범위를 넓히지 않도록 포트에는 숫자 클래스만 쓰고 쿼리 구분자 `?`는 glob에서 이스케이프했습니다. 재조회 결과 실제 변경 필드는 `uri_allow_list` 하나였으며 Google·카카오·SMTP·이메일 확인 등 나머지 Auth 필드는 그대로였습니다. 이미 발급된 로그인 흐름은 이전 복귀 주소를 보관할 수 있으므로, 변경 적용 후에는 로그인 버튼으로 새 흐름을 시작합니다.
