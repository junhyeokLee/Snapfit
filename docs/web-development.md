# 스냅핏 웹 개발

별도 프로젝트 없이 기존 Flutter 앱의 web 타깃을 사용합니다. Supabase의 계정·앨범·Storage·주문 기능을 앱과 공유합니다. 새 유료 서비스는 사용하지 않습니다.

## 웹 디자인 재구성 단계 · 2026-10-15

현재 작업은 웹 전용 화면 구조와 디자인 소스 변경 단계입니다. 사용자의 요청에 따라 이 재구성본은 실행·빌드·브라우저 검증하지 않았습니다. 이전 웹 검수 결과와 스크린샷은 재구성본의 검증 자료가 아닙니다. 기존 로컬 서버가 열려 있다면 그 화면도 이전 빌드입니다.

웹 화면은 모바일 화면을 확대해서 배치하지 않습니다. 웹의 공통 테마·탐색·페이지 틀은 `lib/shared/web/web_design.dart`에 두고, 기능별 웹 표현은 해당 기능의 presentation 아래에서 분리합니다. 모바일과 웹이 공유하는 것은 계정·앨범·저장·가격·주문 상태와 동작입니다. 화면 표현은 `kIsWeb`에서 선택합니다.

| 영역 | 웹 구조 | 재사용하는 동작 |
| --- | --- | --- |
| 공통 | 상단 브랜드와 내 앨범·앨범 만들기·주문내역·계정 메뉴 | 기존 Navigator와 브라우저 경로·권한 확인 |
| 로그인 | 브랜드 소개와 로그인 폼의 2열 구성 | 이메일·Google·카카오 인증·동의·오류 처리 |
| 내 앨범 | 페이지 제목·검색·필터·정렬·앨범 그리드·임시 저장 안내 | 실제 계정의 앨범 조회·즐겨찾기·이어 만들기 |

| 주문내역 | 상태 필터·가로 목록·주문 상세 | 계정별 조회·실제 상태·결제 복구·배송 정보 |
| 계정 | 프로필 요약·이용 정보·설정 섹션 | 기존 프로필·계정 설정·로그아웃 |

### 연결되는 하위 화면까지 적용하는 범위

대표 화면에 그치지 않고 일반 사용자의 실제 이동 경로와 편집 도구까지 웹 전용 표현을 둡니다.

| 흐름 | 웹 전용 구성 |
| --- | --- |
| 메인·앨범 모음 | 공통 상단 탐색, 검색·정렬·필터와 실제 앨범 그리드 |
| 만들기·AI 제작 | 단계 안내, 설정·사진 범위·이용 포인트 확인·추천 검토, 실제 문서 미리보기 |
| 표지·내지 편집 | 문서 도구줄, 페이지 레일, 평면 캔버스와 속성 패널 |
| 편집 하위 도구 | 글 입력·글꼴·색·문구·장식, 사진 구도·프레임, 레이아웃·템플릿 적용 확인을 중앙 Dialog 또는 인라인 패널로 제공 |
| 읽기·페이지 상세 | 문서 보기, 전체 페이지 목록, 현재 페이지 정보와 편집·공유·주문 액션 |
| 공유·초대·수락 | 공유 설정 폼, 권한 요약, 계정·초대 검증에 따른 정상·오류·로그인 상태 |
| 디자인 목록·상세 | 템플릿·소재·내 디자인 보관함, 검색과 필터, 큰 문서 미리보기와 우측 상품 정보·이용 액션 |
| 디자인 하위 도구 | 페이지 확대 뷰어, 템플릿 분량·소재 이용 확인, 적용할 앨범·페이지 선택을 웹 Dialog로 제공 |
| 주문·배송·상세 | 인쇄 검수, 배송지·주소 검색, 주문 금액 요약, 결제 후 상태, 주문내역과 문의·취소·환불 |
| 계정·이용·고객센터 | 로그인·계정 설정, 실제 포인트 잔액과 이용내역, 문의 폼, 알림함·알림 설정, 정책 목록·개별 문서 |

`WebNavigationScope`가 웹 전역 메뉴를 Router로 연결합니다. `/#/designs`, `/#/library`, `/#/notifications`를 추가하며, 브라우저 메뉴 이동도 기존 문서의 저장 확인을 거칩니다. 같은 섹션의 상세 화면에 있더라도 전역 메뉴를 누르면 해당 목록으로 이동할 수 있도록 현재 최상위 경로를 구분합니다.

`showWebAwareDialog`는 창 크기에 맞는 중앙 Dialog의 공통 틀입니다. 네이티브 전용 sheet는 기존 분기로 보존합니다. 사진·문서의 내용과 좌표, 권한·초대·원본·견적 검증은 화면 구성과 분리합니다.

웹에서는 모바일 IAP를 호출하지 않습니다. 포인트 충전용 PortOne V2 경로와 브라우저 푸시를 별도로 준비하며, 실제 웹 결제는 열지 않습니다. 푸시 권한은 사용자가 알림 설정에서 요청할 때만 확인합니다. 개발 주문 도구는 기존 관리자 권한과 TEST 전용 조건을 유지합니다. 별도 운영 프로젝트인 SnapFitAdmin과 일반 사용자 웹에서 진입하지 않는 기존 앱 관리자 3개 화면은 이 고객 웹 재구성 범위와 구분합니다.

이 확장 역시 소스 읽기와 수정만 했으며 앱·브라우저 실행, 포맷·분석·빌드·테스트, 실제 AI 생성·결제·발주를 수행하지 않았습니다. 실제 화면 배치와 컴파일 결과는 이후 검증 대상입니다.

일반 사용자 기능 전체의 앱/웹 대조와 발견한 누락·현재 미지원 범위는 [웹 기능 대조](web-feature-coverage.md)에 기록했습니다. 메인에는 템플릿·꾸밈소재·AI 만들기·내 디자인 보관함 바로가기를 두고, `/#/create/ai`, `/#/designs/materials` 직접 진입도 제공합니다.

### 디자인 기준

- 웹 구조는 시안을 유지하며 색상은 앱의 `SnapFitColors`를 공유합니다. 바탕은 앱의 따뜻한 표면색 `#F7F5F2`, 표면은 흰색, 본문은 `#121212`, 보조 글자는 `#6C6C6C`, 구분선은 `#E6EBEA`입니다.
- 주요 채움은 앱의 청록색 `#08B8D0`, 선택 배경은 `#EAFBFD`, 보조 강조는 보라색 `#8B5CF6`입니다. 밝은 바탕의 강조 글자·아이콘·선택선은 앱 폼과 같은 짙은 청록 `#007E90`, 청록색 버튼 위 글자는 `#063740`으로 구분합니다. 브랜드 아이콘에는 앱의 청록·보라 그라데이션을 사용합니다.
- 앱 공통 색상 파일과 네이티브 테마는 변경하지 않습니다. 앨범 자체의 사진·글·장식·인쇄 색상도 UI 색상 변경 대상에 포함하지 않습니다.
- 일반 콘텐츠는 최대 1320px, 좌우 여백 32px(좁은 웹 20px)입니다. 편집 작업공간은 전체 폭을 씁니다.
- 웹은 고정 글자·여백 체계를 쓰며, 모바일 390px 기준 ScreenUtil 확대 비율을 적용하지 않습니다. 웹 전용 밝게·어둡게·시스템 테마를 제공하고 브라우저에 별도 저장합니다. 모바일의 테마 저장값은 유지합니다.
- 작은 웹 창에서는 열을 줄이고 보조 패널을 접습니다. 모바일 앱의 하단 탭·캐러셀·전면 책 애니메이션으로 되돌리지 않습니다.
- 가상 책등·무대 그림자는 웹 UI에서 제거합니다. 실제 앨범 디자인의 레이어·색·사진·인쇄 비율은 유지합니다.
- 빈 화면·불러오는 중·오류·권한 없음·견적 미확정·판매 준비 중은 실제 상태를 표시합니다. 샘플 가격이나 가짜 주문 완료를 넣지 않습니다.

### 이후 확인할 항목

디자인 구조가 확정된 뒤 별도 요청에 따라 소스 분석·빌드와 브라우저 확인을 진행합니다. 넓은 PC/좁은 웹, 긴 제목, 많은 앨범과 페이지, 폼 오류, 사진 업로드·저장, 로그인 복귀, 브라우저 뒤로가기, 주문 검수·내역을 확인해야 합니다. 이 재구성 단계에서는 새 결제나 발주 테스트를 실행하지 않았습니다.

후속 웹 기능 준비에서 앱을 띄우지 않는 문법·타입 검사를 통과했습니다. 이후 웹 푸시 공개키, 두 DB 마이그레이션과 충전·푸시 서버 함수, PortOne TEST 웹훅·복구 인증·Vault 설정을 반영했습니다. 충전 복구 예약은 비활성으로 등록하고 실행하지 않았으며 실제 결제와 웹 충전 TEST는 계속 닫혀 있습니다. 서비스 워커가 포함된 웹 빌드·호스팅과 앱 실행·결제·웹훅 호출·알림 수신 검증은 아직 하지 않았습니다. 추가한 포인트 충전·푸시·다크 테마의 상세 상태와 남은 확인은 [웹 추가 기능 준비](web-capabilities-preparation.md)를 따릅니다.

## 이후 실행할 때

- 개발: `flutter run -d chrome --web-hostname 127.0.0.1 --web-port 7357`
- 정적 빌드: `python3 tool/build_web.py` (내부에서 Flutter 웹 빌드 후 실행 파일에 콘텐츠 해시를 붙입니다.)
- 빌드 폴더를 정적 웹 서버로 제공하면 됩니다. 기존 Flutter 서비스워커만 해제하고 실행 파일마다 콘텐츠 해시를 사용하므로 이전 앱 캐시가 새 버전을 덮지 않습니다. 로그인 정보나 사진은 지우지 않습니다.
- 기본 해시 경로(`/#/albums/…`)를 사용하므로 새로고침에 별도 서버 경로 처리가 필요하지 않습니다.

## 로그인 설정

웹의 Google·카카오 로그인은 Supabase OAuth를 사용합니다. 모바일의 네이티브 로그인은 유지합니다. 복귀한 세션은 Auth 서버에서 검증한 뒤 사용자 프로필과 동기화합니다.

현재 개발 복귀 주소는 `http://127.0.0.1:7357/?auth_callback=1`과 `http://localhost:7357/?auth_callback=1`입니다. 기존 Supabase 설정을 유지하며 이 두 주소만 추가했습니다. 실제 웹 도메인을 정하면 해당 HTTPS 주소의 `/?auth_callback=1`을 Supabase Auth 허용 목록에 추가해야 합니다. 임의 외부 복귀 주소는 앱이 거부합니다. 제공자 콘솔의 콜백 주소는 Supabase Auth 주소이며 앱 주소와 구분합니다.

## PC 사진과 편집

- JPG·PNG·WebP 파일을 선택하거나 사진 선택창으로 끌어 넣습니다.
- 한 장 50MB, 메모리 보관 최대 100장·총 250MB입니다. 지원하지 않는 형식과 용량 초과는 안내합니다. 원본을 몰래 축소하지 않습니다.
- 원본 바이트·MIME·회전 표시 크기를 보존하고, 편집용 미리보기는 별도로 만듭니다.
- 선택 사진은 저장 전 브라우저 메모리에 있으므로 저장 전 창 닫기·새로고침을 경고합니다. 원본과 미리보기 업로드가 모두 성공해야 저장 완료로 처리합니다.
- 만들기에서 ‘임시 저장’하면 문서와 참조 사진 원본을 같은 브라우저의 계정별 IndexedDB에 함께 보관합니다. 복원 시 사진 ID·크기·원본 해시를 확인합니다. 브라우저 저장 용량 부족/차단은 실패로 처리하고, 다른 기기로 동기화하는 서버 저장과 구분합니다. 모바일의 기존 파일 저장 방식은 유지합니다.
- 웹 편집기는 페이지 목록 / 작업 화면 / 속성 패널을 분리합니다. 좁은 웹에서는 패널을 접으며 모바일 전용 화면으로 전환하지 않습니다.
- Ctrl/Cmd+S 저장, Ctrl/Cmd+Z 실행 취소, Ctrl/Cmd+Shift+Z 또는 Ctrl+Y 다시 실행, Delete/Backspace 삭제, Escape 선택 해제. 텍스트 입력 중에는 문서 단축키를 실행하지 않습니다.

## 페이지 이동과 주문

앨범 읽기·편집·제작 미리보기·주문내역에 브라우저 주소가 생깁니다. 직접 열기와 새로고침은 로그인 후 서버의 접근 권한을 다시 확인합니다. 편집 중 뒤로 가기는 저장 여부 확인을 유지합니다.

계정 개요는 `/#/account` 경로를 사용합니다. 편집 중 전역 이동을 강제로 수행하지 않고 기존 저장·이탈 보호를 거칩니다.

실제 결제·운영 발주 설정은 계속 닫혀 있습니다. 개발 테스트는 기존 PortOne TEST와 레드프린팅 개발 주문 경로를 사용합니다. 일반 주문 화면의 배송·가격 검토는 가능하지만, 실제 결제가 열려 있다고 표시하거나 결제되지 않은 주문을 완료로 표시하지 않습니다. 이번 웹 UI 변경은 인쇄 서버·가격·실판매 설정을 변경하지 않습니다.
